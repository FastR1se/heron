# Перед отправкой

Разработка на Windows, тесты на Linux, между ними GitHub. Круг «push → CI → разбор лога»
длинный, а большая часть того, что CI проверяет, не требует ни ROS 2, ни симулятора и
прекрасно идёт здесь.

```
python .claude/skills/preflight/run.py
```

Около 2,5 минут: линтер, `mypy` ядра и двух пакетов, набор ядра, наборы пакетов роботов и
задач, цепочка CLI на dummy (валидация, `gen --check`, командный класс, отказ прогона на
железе без шкалы, миссия комплекса), `bash -n` по всем установщикам. Останавливается на первом
отказе и печатает команду с хвостом вывода.

```
python .claude/skills/preflight/run.py --quick
```

Около 75 секунд: линтер, типы, набор ядра. Для проверки посреди работы.

## Как читать вывод

- `[ + ]` — шаг прошёл.
- `[ ~ ]` — пропущен, потому что на машине нет входа: описания производителя не загружены
  (`scripts\dev-setup.ps1 -Descriptions`). CI его не пропустит.
- `[ ! ]` — отказ; дальше не идём. Часть шагов **обязана** завершиться неудачей (прогон на
  железе без `--speed-scale`, потоковый навык на командном RC5) — для них `[ + ]` значит, что
  отказ получен.

## Чего здесь нет

Эти задания CI требуют чистой установки или Linux, и локально не воспроизводятся:

| Задание CI | Почему только там |
|---|---|
| «Инвариант 1 — ядро без роботов» | удаляет `examples/` и ставит ядро заново |
| «Ядро ставится без вендорских зависимостей» | venv без единой дополнительной группы |
| «Критерий 10 — заготовка робота пользователя» | ставит порождённый пакет в чистое окружение |
| `install.sh check/status` | нужен Linux и apt |
| Всё с ROS 2, Gazebo, MuJoCo, DDS, Isaac | стек стоит на Linux-машине |

Если правка трогает `pyproject.toml`, entry points, импорты верхнего уровня или `scripts/` —
эти четыре задания и есть та половина, которую проверит только CI. Стоит сказать об этом в
сообщении, а не считать прогон полным.
