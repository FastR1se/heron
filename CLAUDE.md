# CLAUDE.md — инструкция агенту

**Heron** (имя рабочее) — платформа моделирования гетерогенных робототехнических комплексов:
декларативный профиль робота → генерация сред (URDF/SDF/USD, launch) → навык кодом или
обученная политика за одним интерфейсом → симуляция → железо. Новизна — в **валидаторе**:
рассогласование сред ловится до запуска. Работа исследовательская: записка собирается из
журналов, ход разработки — такой же результат, как код.

Здесь только правила поведения. Система — `ARCHITECTURE.md` (источник правды), обоснования — `docs/decisions/`.

## Рабочие правила

- Разработка — Windows, тесты — Linux, обмен — GitHub `https://github.com/FastR1se/heron.git`.
- **Всё на диске D**, включая временные файлы и кэши инструментов (на C ~2.8 ГБ): путь кэша задаётся явно.
- Новая часть разработки — новая сессия; напоминать пользователю, когда часть закрыта.
- Документация, журналы, коммиты — по-русски; код, имена, docstrings — по-английски.

## Семь инвариантов (раздел 2 архитектуры)

Нарушение — остановиться и переделать, без компромисса.
1. В ядре нет имён роботов: удалили `robots/` — ядро собирается и проходит тесты.
2. Границы миров — файлы: из обучения выходят только артефакты (ONNX + контракт).
3. Один образ — две среды: между симуляцией и железом меняется только конфиг адаптера.
4. Миссия не знает, как сделан навык: кодовый → обученный — одна строка профиля.
5. Профиль — данные: новый робот — YAML (+ внешний плагин), без правок ядра.
6. Контракт проверяется до запуска: рассогласование — ошибка валидатора.
7. Возможности, а не типы: ядро не знает слов «гуманоид», «манипулятор».

Сквозной принцип: **величина описывается один раз и там, где достоверна** — перед новым полем проверить `contract` и `limits`.

## Журналы — в момент события, не по памяти задним числом

| Файл | Содержание | Когда |
|---|---|---|
| `docs/journal/YYYY-MM-DD.md` | `Задача`, `Сделано`, `Проблемы и тупики`, `Наблюдения`, `Дальше` | конец каждой сессии |
| `docs/decisions/NNNN-<тема>.md` | `Статус`, `Дата`, `Контекст`, `Решение`, `Альтернативы` (причина отказа каждой), `Последствия` | любой выбор, влияющий на структуру |
| `docs/experiments/NNNN-<тема>.md` | версии всех сред, машина, зерно ГСЧ, id артефакта политики, сырые числа, путь к записи прогона | каждый измерительный прогон |
| `CHANGELOG.md` | что изменилось для пользователя | каждая завершённая фаза |

- «Проблемы и тупики» заполняются всегда, даже если от попытки не осталось кода: отрицательный результат — материал главы об обосновании решений.
- Карточки: нумерация сквозная, задним числом не правятся; изменение решения — новая карточка «заменяет» со ссылкой.
- Медиа (гифки, графики, снимки) — в `docs/media/` сразу при получении: первый успех не переснять.

## Правила кода

- **Имя платформы литералом не пишется нигде** (CLI, пути, переменные окружения, поиск плагинов) — только `src/heron/core/branding.py`. В схемах данных имени нет, только `schema_version`. Имена топиков и узлов ROS 2 — от id робота.
- Стек: Python 3.11+, pydantic + YAML (строгие схемы), Typer, uv, ROS 2 Jazzy, Gazebo Harmonic, MuJoCo, Isaac Lab 2.3, rsl_rl, Foxglove/RViz, хранилище — файлы + JSON, Docker Compose. Свой дашборд, MLflow, Kubernetes — не пишем.
- Ядро ставится без вендорских зависимостей; вендорское — `examples/` и опциональные группы, подключение через entry points.
- Расширение — только шесть точек: `ControlAdapter`, `Skill`, `SimBackend`, `TrainBackend`, двойник (0021), задача обучения (0044). Новая точка — решение, не правка.
- Костыли запрещены: нужен обход — значит, ошибка выше по течению; искать её.

## Готовность задачи

1. Код проходит тесты. 2. Журнал сессии, включая «Проблемы и тупики». 3. Новые выборы — карточками.
4. Коммит ссылается на применённое решение: `feat(core): control_mode в профиле (ADR-0007)`.
5. Закрытие фазы (раздел 14) — плюс `CHANGELOG.md` и итог: что доказано, что осталось.

## Принятые решения (ADR-NNNN)

Противоречие коду — ошибка кода. Здесь — суть; **перед работой в области прочитать полную
карточку** `docs/decisions/NNNN-*.md`. Новое решение — одна строка сюда.

**Контракт, профиль, валидатор**
- **0001** Возможность — ровно `<домен>.<аспект>`, реестр закрыт, сторонние — `x_`, без параметров. Количества — `requires` только с `>=`, `<=`, `==` (до выражений не расширять). Сопоставление — равенство множеств, без вывода.
- **0004** `contract_id = sha256(каноническая JSON нормативных полей)[:16]`; совместимость — равенство id, при расхождении печатать различие по полям. Содержимое изменилось, `revision` нет — ошибка.
- **0006** Каноническая форма: ключи отсортированы, без пробелов, ASCII, кратчайшие обратимые числа; золотой тест. Нормативные — все поля `Contract`, кроме `revision`. `contracts.lock.json` пишет только `contract lock`, валидатор — никогда.
- **0007** Валидатор → `Report` из `Finding`: код `<область>.<правило>`, severity, подсказка, ссылка на решение, подробности. Коды — публичный API, тесты проверяют коды, не тексты. CLI: 0 чисто, 1 ошибки, 2 вход не читается.
- **0008** Величины `requires` — закрытый реестр, один источник в профиле: `dof`, `command_rate_hz`, `state_rate_hz`, `cartesian_velocity_max`, `gripper_width_m`. Чужое имя — ошибка разбора; необъявленная величина — невыполненное требование.
- **0019** `kp`/`kd` — нормативные поля действия: по суставу в порядке `joint_order`, оба или никак, только `joint_position` и `rad`. С ними — интерфейс `effort` и `joint_trajectory_controller` с `gains`.
- **0041** `default_pose`, `action.scale` по суставу, `action.offset: zero | default_pose`; `q* = clip(a) ⊙ scale + origin` в обоих мирах, клип над сырым выходом. Незаданное необязательное нормативное поле в каноническую форму не попадает. Цели вне `limits.joint_position` или масштаб без `clip` — `contract.action_outside_limits`.
- **0042** Термы суставов — ровно `joint_order` в его порядке; `joint_pos_rel`, `target_joint_pos`; `previous_action` — после clip, до масштаба, на первом такте нули. Шума и клипа термов нет, нормализатор — в ONNX. Ширины выводятся.

**Описания, генерация, мир**
- **0002** Один `world.backend` на сценарий — один владелец физики; робот без адаптера под него — ошибка валидатора. Сцена двух движков — не-цель.
- **0009** `description.urdf` и `world.file` — входы, не изменяются. Генераторы порождают только выводимое (`ros2_control`, контроллеры, мир, запуск, визуализация); итоговый URDF — копия входа со склейкой. Сверка — правила `urdf.*`.
- **0010** Порождается описание, не код: XML — `xml.etree`, YAML — `yaml.safe_dump`, шаблонизатора нет. Выход — один неверсионируемый каталог, генерация детерминирована (`gen --check`), шапка с источником и `contract_id`.
- **0012** Команды — по контракту, состояния — по описанию: сустав вне `joint_order` получает только интерфейсы состояния. Роль `static` → `joint_state_publisher`.
- **0013** Пакеты ROS 2 запуска — `LAUNCH_PACKAGES`, равный установке фазы 0 (тест с двух сторон). Новый узел — изменение требований к окружению.
- **0014** Имена управляющего слоя — только `ros2/names.py`. Транспорт внедряется, адаптер сообщений ROS 2 не строит, импорт ROS 2 — в `connect`. Порядок суставов — по именам, недостающий — ошибка.
- **0017** Копия описания ссылается на меши абсолютными `file://`; разрешение одно — `core.urdf.resolve_mesh`; `package://`, `model://` не трогаются.
- **0018** Свободную базу платформа не закрепляет: `low` без фиксированного сустава к `world` — предупреждение `urdf.free_base_uncontrolled`.
- **0031** `description.mjcf` — второе описание; `core.mjcf` на stdlib (включения, `<default>`, градусы → радианы). Правила `mjcf.*`; расхождение с URDF — предупреждение с обоими числами, допуск 10⁻⁵.
- **0048** USD — порождённый кэш `data_home()/cache/usd/<ключ>/`, не в репозитории и не в артефакте; `merge_fixed_joints=False`. База закрепляется только `fixed_to_world` из описания.
- **0055** `description.urdf` обязателен и без симуляции. RC5 — руками по DH: кинематика, у каждого числа источник, звено `world`; соглашение DH проверяется пробой.

**Симуляция и двойники**
- **0011** `SimBackend` — оркестратор процессов через внедряемый запускатель; `build_world` отказывается строить сцену, не прошедшую валидатор. Тесты доказывают состав команд, не запуск.
- **0020** Мир комплекса — Gazebo; гуманоид — через DDS производителя (мост: `LowCmd`/`LowState`, закон привода синхронно с физикой). Один DDS-адаптер вне ядра для моста, двойника MuJoCo и железа. MuJoCo — эталон и sim2sim, не в сцене комплекса.
- **0021** Пакет робота = адаптер + двойник на пару «адаптер, бэкенд». Двойник объявляет процессы, род (владеет физикой / мост), требования; связь — из `params`. `ros2_control` в Gazebo — такой же двойник.
- **0023** Эталонный двойник — `unitree_mujoco` без правок, закреплённые коммиты, аргументы `-r -s -i -n`. Метка времени — `LowState.tick` (время мира). Пиры объявляет только адаптер.
- **0024** `Twin` в ядре (`adapter`, `backend`, `kind`) + протокол бэкенда (`GazeboTwin`). Поиск по паре, два на пару — ошибка. Генераторы не знают `ros2_control` по имени. `twin.*` — для установленного бэкенда и управляемых роботов. Пакет робота импортирует только `PUBLIC_MODULES` (тест).
- **0030** Бэкенд `mujoco` запускает двойника (`MujocoTwin.processes` → `TwinProcess`), MuJoCo не импортирует; только «владеет физикой», один участник. Сцена — `world.file`; шаг сверяется с `state_rate_hz`. Падение до первой команды — условие прогона.
- **0033** Мост G1 в Gazebo — двойник прошивки: `unitree_g1_bridge/LowLevelBridge` в пакете робота; закон в `update()` по последнему `LowCmd`, `mode = 0` — без момента, `tick` — мс мира. Параметры — из Python, тест держит имена C++ и Python вместе. `ros2_control` для G1 закрыт.
- **0034** `GazeboTwin.environment(instance)` → `<set_env>` в начале запуска; разные значения одной переменной — отказ. G1: `rmw_cyclonedds_cpp`, домен, `CYCLONEDDS_URI` как у канала. Фиксированные топики — в корне, один такой робот на домен; общий топик двух роботов — отказ.
- **0035–0037** Мир — группа процессов (своя сессия на POSIX). Gazebo — SIGINT группе (как Ctrl+C), MuJoCo — TERMINATE; `wait()` ждёт опустения группы; просят один раз, дальше SIGKILL группе. Запускатель сбрасывает SIGINT ребёнка в `SIG_DFL`; `sim run` сводит SIGINT и SIGTERM в одну остановку.

**Окружение**
- **0022** CycloneDDS 0.10.2 из исходника вне системных путей; 0.11+ запрещён у всех, кто встречается с 0.10.2. DDS-процесс не грузит `rclpy`. Конфигурацию строит транспорт; от SDK — только IDL и CRC. Связь (домен, интерфейс, пиры) — в `params`.
- **0025** Требования — `Requirement` (виды `python`, `ros2`, `executable`, `variable`; PEP 440; нужно/запрещено с причиной). Объявляют `ControlAdapter` и `Twin`, без умолчания. Проверяется машина, не в `validate`: `env check`, `sim run`, `run`. Версия не определяется — нужное не выполнено. Без импорта.
- **0039** `run` работает в окружении мира, выведенном из двойников (как 0034), до требований адаптера и `connect`; другое значение переменной — отказ с обоими; двойник не найден — отказ.
- **0071** Установка — один вход `scripts/install.sh`; окружение пакета робота ставит его `examples/plugins/<пакет>/install.sh` в `~/robot-stack/<пакет>`, платформа имён не знает. Окружения — `source scripts/activate.sh`. Пакеты — `uv pip install -e` во все venv, не `uv sync`. Main — `<следующая>.dev0`. `scripts/`: `tools/`, `runs/` (незакрытые этапы), закрытое удаляется.

**Исполнение и навыки**
- **0015** Темп — `command_rate_hz` от начала такта. Сторож — из `state_rate_hz` (10 периодов, ≥ 0.5 с), полем не объявляется. Свежесть — внедряемые настенные часы, время мира — метки адаптера. Сработал — сначала останов, потом отчёт. Последовательность рвётся на первом отказе. `run_skill` — тот же исполнитель.
- **0016** Первое чтение ждёт `link_timeout`, дальше — один такт. `poll` блокирует до `timeout`. Один исполнитель на связь. Нет издателя ≠ молчит издатель (`publisher_count`).
- **0026** Отказ — `CommandRefusedError`, ничего не отправлено. Исполнитель: `emergency_stop` → отмена навыка → `FAILURE`; другое исключение — останов и проброс; неудачный останов дописывается к причине. Отказ называет сустав, значение, пределы.
- **0032** Навык от измеренной позы стартует с её проекции на `limits.joint_position` (`skills.base.admissible`), перенесённые — в журнал. Адаптер отказывает всему вне рамки, допуска нет.
- **0038** Запись прогона — исполнитель через внедряемый `Recorder`: MCAP, JSON-каналы `/state`, `/command`, без ROS 2; `mcap` — группа `record`. `log_time` — часы исполнителя, `publish_time` — мир. Метаданные `run` до первого такта, `result`/`interrupted` при закрытии. `run --record`; метрик в записи нет.
- **0049** Командный класс — навык `goto_joints` (`target`, обязательный `tolerance`, одна команда на движение); `RobotState.motion`: `idle`/`moving`/`halted`, у потоковых `None`. Адаптер защёлкивает фазу, отказывает в команде во время движения, берёт v/a из `limits.joint_velocity`/`joint_acceleration`, отзывает движение при `disconnect`. `SUCCESS` — `idle` и поза в допуске. Режимы — равенство.
- **0050** Командный класс — тот же цикл: `command_rate_hz` — период решения, `state_rate_hz` — публикация робота, метка — часы робота; сторож замечает, а не защищает. Поза, метка, фаза — из одного чтения.

**Прогон на железе и адаптеры**
- **0051** Цель `run`: `sim.<бэкенд>` или `real`, миссия одна. На `real` окружение мира не применяется, сценарий проверяется целиком (мир — `dummy`); без `limits.joint_position`/`joint_velocity` — `real.limits_missing`. `world.backend: real` и `deploy` не вводятся.
- **0052, 0057** `run --speed-scale s`, `0 < s ≤ 1`, на `real` обязателен. Движение по `s·v` и `s²·a`. Адаптер объявляет `supports_speed_scale: bool` на классе без умолчания; при `False` получает только `s = 1`. `speed_scale` в `params` профиля — ошибка. Применённая шкала больше запрошенной — отказ. Шкала — в плане и записи.
- **0053** SDK не реагирует за платформу: RC `ignore_controller_exceptions=True`, статус безопасности → `halted` и отказ команды. `RobotApi` — только в `connect`, `sys.excepthook` возвращается, `disconnect` SDK на всех путях, журнал SDK — в логгер процесса.
- **0054** RC: `params.model == robot_model`, число суставов SDK = контракт. Питание и тормоза не трогает: контроллер не в `run` — отказ, тормоза снимает человек. Подтверждение позиции всегда отказывает.
- **0056** Контрактный набор — `testing.adapter_contract` (публичный): пакет наследует `AdapterContract` со своей `Harness`. Тесты платформы — только встроенные адаптеры. `new-robot --control-mode` порождает пакет с тестом набора.
- **0058, 0060** `ros2_control`: поток — траекторный контроллер только как закон привода с коэффициентами; командный класс — цели `FollowJointTrajectory` по трапеции `adapters.motion` (общей с `dummy`), `s·v`, `s²·a`, выборка на `state_rate_hz`. `moving` до «цель окончена» и следующего состояния (`extra["motion_ended"]`); отказ — `GoalRefusedError`; отмена при `emergency_stop`/`disconnect`. Поток со шкалой ≠ 1 — отказ. Только радианы.
- **0061** Аварийный останов RC — `mode.set("hold")`: удержание, буфер сброшен, питание и тормоза не трогаются; остановленным считается до отправки, принятое движение — `halted`. Без связи — `StopNotDeliveredError` к причине прогона, переподключения нет. Пропажа связи — молчание для сторожа, не исключение `read_state`. Принято до пробы (факты 0.25, 0.44, 0.46).
- **0062** Канал RC читает RTD закрытым приёмником SDK (`_rtd_receiver`) версии, закреплённой `API ==1.4.1`: копия одним выражением, маркеры `0x12`/`0x21` в каждом показании (сдвиг — молчание), новое показание — только с новой парой `sec`/`nsec`.

**G1**
- **0027, 0059** Слоты — раскладка 29 приводов в пакете, сустав находит слот по имени, пустой — `mode 0` и нули; сверка с порядком MJCF. `mode_machine` первого `LowState` называет тело по таблице производителя (`MACHINES`: 4, 5, 6); тело ≠ контракту или неизвестное значение — отказ при `connect`.
- **0028** Аварийный останов — одна команда демпфирования (`kp = 0`, `kd` из контракта, пустые слоты выключены), без зависимости от свежести позы; остановленным считается до отправки.
- **0029** Канал DDS — протокол пакета: на границе `LowCommand`/`LowStateReading`, канал только переводит и считает CRC. `cyclonedds` напрямую, импорт при открытии, процесс с `rclpy` отвергается. `params`: `domain`, `interface` обязательны, `peers` — по желанию.
- **0064** Контракт G1 — всё тело или тело без ног; второй — только у профиля без `real` (отказ до открытия канала). Мост Gazebo принимает верх тела только на описании с `fixed_to_world`, двойник MuJoCo — отвергает.

**Обучение**
- **0003** Траектории: MCAP на исполнении, `.npz` + тот же JSON-контракт в обучении, одно явное преобразование в CLI. ROS 2 в окружение обучения не попадает.
- **0005** Локомоция вне объёма; обучаемый навык — задачная политика гуманоида на встроенном балансе. Ubuntu 24.04 (не WSL2), только headless, камер в наблюдениях нет. Go/no-go до фазы 6: ≥ 512 сред, VRAM ≤ 7 ГБ, RAM ≤ 13 ГБ, ≤ 6 ч; не выполнено — MuJoCo + rsl_rl без попыток выжать.
- **0040** Фаза 6: сначала `arm6` проводит весь конвейер (Isaac → ONNX + контракт → `LearnedSkill` → Gazebo), затем G1; закрывается после обеих. Порог 0005 — до кода бэкенда обучения. План — `docs/plans/phase6-learned-skill.md`.
- **0043** Цель обученного навыка — `target`. `SUCCESS` — `max|q − target| ≤ tolerance` в течение `hold_s` мира, `FAILURE` — за `horizon_s`; все три — от задачи, в манифесте. Нет терма цели — `policy.completion_undefined`.
- **0044** Бэкенд `isaaclab` в ядре; `TrainSpec` — данные без Isaac (`dt = 1/state_rate_hz`, целое `decimation`, остальное из контракта); процесс `sys.executable -m …` со `spec.json`. Нужны `isaaclab`, `isaacsim`, `rsl_rl`, запрещён `rclpy`. Задача — шестая точка (`train_tasks`): `TrainTask` + `IsaacLabTask`; действие, наблюдение, привод, частоты не меняет. `learner` требует `task`, один на сценарий.
- **0063** Баланс G1 в симуляции не моделируется: таз закреплён во входе-описании (`world_joint` на 1.0 м, пишет `fetch_description.py`), обучается политика верха тела (15 суставов), ноги вне контракта. Это не «встроенный баланс» 0005 — условие каждого прогона. Уровень `low`, без `real` и мира MuJoCo.
- **0045** Закон привода один: `tau = kp·(q* − q) − kd·dq` на `state_rate_hz`, момент в пределе URDF. Isaac — `IdealPDActuator`, шаг `1/state_rate_hz`; Gazebo — `interpolation_method: none`, `time_from_start: 0`, нулевые `velocities`.
- **0046** Артефакт — `store_root()/policies/<name>/<artifact_id>/` (`policy.onnx`, `manifest.json`, `train.json`), `artifact_id = sha256(канонический манифест)[:16]`, манифест держит хеш ONNX и completion. Прогоны — `data_home()/train/…`. Ссылка `<name>@<id>`, привязка в `skills`; необъявленный навык — `scenario.skill_not_in_profile`. Нет артефакта: `validate` — предупреждение, `run` — ошибка.
- **0047** `LearnedSkill` в ядре; сверка (`policy.*`, различие контрактов) — до требований и `connect`. `onnxruntime` — группа `onnx`, CPU, один поток. Такт: наблюдение → сеть → клип → отображение → команда → завершение. Отказ — 0026; 0032 не применяется.

**Комплекс (координатор)**
- **0065** Миссия — YAML в своём файле, роботов не называет: задача — `skill`, `goal`, `required_capabilities` и `requires` сверх навыка, `after`, `robot`. Команды принимают сцену и миссию; `Scenario.task` остаётся для `run`.
- **0066** Задача достаётся ровно одному кандидату до запуска: профиль объявляет навык, проходит `check_skill_against_profile`, возможности и `requires` задачи. Ни одного — `mission.task_unassigned`, несколько — `mission.task_ambiguous`; `robot` сужает круг (`mission.robot_unknown`).
- **0067** `after` — только задачи выше (`mission.dependency_unknown`, `mission.dependency_forward`); умолчание — предыдущая, `[]` — не ждать. Задачи одного робота — в порядке файла. Условие одно — успех; деревьев поведения нет.
- **0068** Координатор — процесс `mission run`, каждый робот — процесс `mission robot` со своим исполнителем; план — `plan.json` с `plan_id`; связь — строки JSON по TCP на 127.0.0.1 (`welcome`/`rejected` до `connect`). `--no-spawn` — роботы из разных окружений. `run` не меняется.
- **0069** Первая неуспешная задача останавливает комплекс: идущие отменяются (сначала `emergency_stop`), новые не начинаются, стоящие не трогаются. Ctrl+C — та же остановка, исход `interrupted`.
- **0070** Прогон миссии — каталог: `plan.json`, `events.jsonl` по ходу, `result.json` в конце; с `--record` — MCAP на задачу по 0038 с `mission`, `task`, `plan` в метаданных.
