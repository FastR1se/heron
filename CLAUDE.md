# CLAUDE.md — инструкция агенту разработки

Читается в начале каждой сессии. Здесь только то, что меняет поведение при работе:
рабочие правила, обязательные ритуалы и запреты. Описание системы — в `ARCHITECTURE.md`,
он источник правды. Обоснования решений — в `docs/decisions/`.

---

## Что за проект

**Heron** (имя рабочее, см. раздел 17 архитектуры) — платформа моделирования
гетерогенных робототехнических комплексов. Один декларативный профиль робота →
генерация сред (URDF/SDF/USD, launch, compose) → навык кодом или обученная политика
за одним интерфейсом → проверка в симуляции → перенос на железо. Новизна платформы
сосредоточена в **валидаторе**: он ловит рассогласование сред до запуска, а не на роботе.

Работа исследовательская: пояснительная записка собирается из журналов. Ход разработки —
такой же результат, как код.

---

## Рабочие правила

- Разработка идёт на **Windows**, тестирование — на **Linux**-машине, обмен через
  **GitHub**: https://github.com/FastR1se/heron.git
- **Все файлы на диске D**, включая временные. На C места нет (~2.8 ГБ). Это касается
  и кэшей инструментов: если инструмент по умолчанию пишет в профиль пользователя,
  его путь задаётся явно.
- **Каждая новая часть разработки — новая сессия.** Напоминать об этом пользователю,
  когда текущая часть закрыта.
- Язык документации, журналов и сообщений коммитов — русский. Язык кода, включая
  имена и docstrings, — английский.

## Семь инвариантов

Нарушение любого — повод остановиться и переделать, а не искать компромисс.
Полные формулировки — раздел 2 архитектуры.

1. **В ядре нет имён роботов.** Проверка: удаляем `robots/` — ядро собирается и проходит тесты.
2. **Границы миров — файлы.** Из обучения наружу выходят только артефакты (ONNX + контракт).
3. **Один образ — две среды.** Между симуляцией и железом меняется только конфиг адаптера.
4. **Миссия не знает, как сделан навык.** Замена кодового навыка на обученный — одна строка в профиле.
5. **Профиль — данные, не код.** Новый робот не требует правок ядра: YAML плюс, при нужде, внешний плагин.
6. **Контракт проверяется до запуска.** Рассогласование сред — ошибка валидатора, а не странное поведение робота.
7. **Возможности, а не типы.** Ядро не знает слов «гуманоид» и «манипулятор».

Сквозной принцип, выведенный из первых пяти решений:
**величина описывается один раз и там, где она достоверна.** Прежде чем добавить поле,
проверить, не задана ли эта величина уже в `contract` или `limits`.

## Журналы — обязательная часть работы

Раздел 18 архитектуры требует дублировать это правило здесь, чтобы записи появлялись
по ходу работы. Главное: **записи делаются в момент события, а не восстанавливаются
потом по памяти и коммитам.**

| Файл | Что фиксирует | Когда |
|---|---|---|
| `docs/journal/YYYY-MM-DD.md` | Ход работы | Каждая сессия, в конце |
| `docs/decisions/NNNN-<тема>.md` | Архитектурные решения | При любом выборе, влияющем на структуру |
| `docs/experiments/NNNN-<тема>.md` | Постановка, условия, числа, выводы | Каждый измерительный прогон |
| `CHANGELOG.md` | Что изменилось для пользователя | Каждая завершённая фаза |

**Журнал сессии** — разделы `Задача`, `Сделано`, `Проблемы и тупики`, `Наблюдения`, `Дальше`.
Раздел «Проблемы и тупики» заполняется всегда, даже если в коде от неудачной попытки не
осталось следа: отрицательный результат — материал главы об обосновании решений.
Без него вместо исследования получается отчёт о программировании.

**Карточка решения** — `Статус`, `Дата`, `Контекст`, `Решение`, `Альтернативы` (с причиной
отказа по каждой), `Последствия`. Нумерация сквозная. **Записи не редактируются задним
числом:** изменение решения — новая карточка со ссылкой на предыдущую и статусом «заменяет».

**Эксперимент** — обязательно версии всех сред, конфигурация машины, зерно ГСЧ,
идентификатор артефакта политики, сырые числа, путь к записи прогона.

**Медиа** — гифки, графики и снимки экрана складываются в `docs/media/` сразу при
получении. Переснять момент, когда что-то заработало впервые, потом невозможно.

## Принятые решения

Учитывать при написании кода; противоречие коду — ошибка кода.

| № | Решение |
|---|---|
| [ADR-0001](docs/decisions/0001-capability-format.md) | Возможность — ровно два сегмента `<домен>.<аспект>`, реестр в ядре закрыт, сторонние — в домене `x_`. Параметров внутри нет. Количественные требования навыка — блок `requires` со сравнениями `>=`, `<=`, `==`; расширять его до выражений запрещено. Сопоставление — только равенство множеств, без вывода следствий |
| [ADR-0002](docs/decisions/0002-single-physics-authority.md) | Один `world.backend` на сценарий — один владелец физики. Робот без адаптера под этот бэкенд — ошибка валидатора. Совместная сцена двух движков — не-цель, не отложенная задача |
| [ADR-0003](docs/decisions/0003-trajectory-format.md) | Траектории: MCAP на исполнении, `.npz` плюс тот же JSON-контракт в обучении, одно явное преобразование через CLI. ROS 2 в окружение обучения не попадает |
| [ADR-0004](docs/decisions/0004-contract-identity.md) | `contract_id = sha256(каноническая JSON-сериализация нормативных полей)[:16]`. Нормативные: `joint_order`, `angle_unit`, `observation` со `scale` и порядком, `action.type`, `action.clip`, `command_rate_hz`, `state_rate_hz`. Совместимость — равенство идентификаторов; при расхождении печатается различие по полям, а не факт «хеши разные». Рядом `revision: int`: содержимое изменилось, а `revision` нет — ошибка валидатора |
| [ADR-0005](docs/decisions/0005-training-resources.md) | Локомоция вне объёма работы; обучаемый навык — задачная политика гуманоида с балансом на встроенном контроллере. Родная Ubuntu 24.04, не WSL2. Обучение только headless, камеры в наблюдениях запрещены. Порог go/no-go до фазы 6: ≥512 сред, пик VRAM ≤7 ГБ, пик RAM ≤13 ГБ, прогон ≤6 ч. Не выполнено любое условие — запасной путь MuJoCo + rsl_rl, без попыток выжать остаток |
| [ADR-0006](docs/decisions/0006-contract-canonical-form-and-lock.md) | Каноническая форма контракта зафиксирована (ключи отсортированы, без пробелов, ASCII, числа в кратчайшем обратимом виде) и покрыта золотым тестом. Нормативные поля — все поля класса `Contract`, кроме `revision`. Предыдущее состояние контрактов хранит `contracts.lock.json` в корне реестра; пишет его только команда `contract lock`, валидатор не обновляет его никогда |
| [ADR-0007](docs/decisions/0007-validator-findings.md) | Валидатор возвращает `Report` из структурных `Finding` с устойчивым кодом `<область>.<правило>`, severity, подсказкой, ссылкой на решение и машиночитаемыми подробностями. Коды — публичный API, тесты проверяют их, а не формулировки. Коды возврата CLI: 0 — чисто, 1 — ошибки, 2 — вход не читается |
| [ADR-0008](docs/decisions/0008-requires-registry.md) | Величины блока `requires` — закрытый реестр, у каждой ровно один источник в профиле (`dof`, `command_rate_hz`, `state_rate_hz`, `cartesian_velocity_max`, `gripper_width_m`). Имя вне реестра — ошибка разбора. Величина, которой профиль не объявляет, считается невыполненным требованием, а не пропущенной проверкой |
| [ADR-0009](docs/decisions/0009-generators-do-not-author-kinematics.md) | `description.urdf` — вход платформы, а не выход. Генераторы порождают только выводимое: блок `ros2_control`, конфигурацию контроллеров, мир, запуск, визуализацию. Итоговый URDF — копия входа с вклеенной склейкой; вход не изменяется никогда. Заданный сценарием `world.file` — тоже вход. Взамен авторства — семейство правил `urdf.*`, сверяющих описание с профилем с переводом единиц |
| [ADR-0010](docs/decisions/0010-generated-artifacts.md) | Порождается описание, а не код: файл запуска — XML. Шаблонизатора нет, XML собирается `xml.etree`, YAML — `yaml.safe_dump`. Выход — один каталог, не версионируется. Генерация детерминирована, отсюда `gen --check`. Каждый файл открывается шапкой с источником и `contract_id`. Foxglove и `compose.yaml` на фазе 2 не порождаются осознанно |
| [ADR-0011](docs/decisions/0011-sim-backend-runs-processes.md) | `SimBackend` — оркестратор процессов, а не ссылка на тела сцены. Процессы запускаются через внедряемый запускатель, поэтому команды проверяемы до запуска. `build_world` отказывается строить сцену, не прошедшую валидатор. Тесты доказывают состав команд и ничего не говорят о том, что симулятор от них поднимется |
| [ADR-0012](docs/decisions/0012-observe-everything-command-the-contract.md) | Состав командных интерфейсов задаёт контракт, состав интерфейсов состояния — описание. Подвижный сустав описания вне `joint_order` получает только интерфейсы состояния: командовать им платформа не может по построению, но читает его. Робот с ролью `static` получает `joint_state_publisher` вместо контроллеров. Наблюдение — предпосылка проверки: сустав, который никто не читает, не сверить ни с чем |
| [ADR-0013](docs/decisions/0013-launch-depends-only-on-the-declared-environment.md) | Набор пакетов ROS 2, на которые ссылается порождаемый запуск, объявлен в коде (`LAUNCH_PACKAGES`) и совпадает с тем, что ставит фаза 0; совпадение проверяется тестом с двух сторон. Файл запуска не деградирует: отсутствие пакета убивает всю сцену, а не ту её часть, ради которой узел добавлен. Новый узел — изменение требований к окружению, а не строка в генераторе |
| [ADR-0014](docs/decisions/0014-control-plane-names-have-one-home.md) | Имена управляющего слоя — контроллер, его класс, топики, типы сообщений — выводятся в `ros2/names.py`, который читают и генератор, и адаптер. Место публикации состояний объявляется параметром, а не наследуется по умолчанию. Топики ведомых роботов пишутся в манифест набора. Транспорт внедряется, адаптер отдаёт ему значения и сам сообщений ROS 2 не строит; импорт ROS 2 — внутри `connect`. Порядок суставов восстанавливается по именам, недостающий сустав — ошибка, а не ноль |
| [ADR-0015](docs/decisions/0015-executor-paces-and-watches.md) | Исполнитель ведёт темп по `command_rate_hz`, считая период от начала такта. Порог сторожевого таймера выводится из `state_rate_hz` (десять пропущенных периодов, не менее 0.5 с) и полем не объявляется. Свежесть меряется настенными часами, время мира — метками адаптера; часы внедряются. Сработал таймер — сначала останов робота, потом отчёт. Последовательность задач прерывается на первом отказе. Цикл один: `run_skill` — тот же исполнитель с неидущими часами |
| [ADR-0016](docs/decisions/0016-establishing-a-link-is-not-using-it.md) | Первое чтение состояния ждёт установления связи по отдельному сроку (`link_timeout`), последующие — один такт: «сколько ждать сообщение в такте» и «сколько ждать, пока связь появится» — разные величины. Это срок на условие, а не пауза. `poll` обязан блокировать до `timeout` — записано в протокол. Один исполнитель на время жизни связи. Отсутствие издателя и молчание издателя различаются в сообщении об отказе (`publisher_count`) |
| [ADR-0017](docs/decisions/0017-generated-description-anchors-meshes.md) | Порождённая копия описания ссылается на меши абсолютными `file://`-URI, разрешёнными от входа. Разрешение ссылки одно — `core.urdf.resolve_mesh`, его читают и правило `urdf.mesh_not_found`, и генератор. `package://` и `model://` не трогаются. Вход не изменяется |
| [ADR-0018](docs/decisions/0018-free-base-is-a-run-condition.md) | Свободную базу платформа не закрепляет. Уровень `low` при описании без фиксированного сустава к звену `world` — предупреждение `urdf.free_base_uncontrolled`: условие прогона, объявленное до него, а не дефект |
| [ADR-0019](docs/decisions/0019-drive-gains-are-part-of-the-action.md) | `kp` и `kd` — нормативные поля действия контракта: по суставу, в порядке `joint_order`, вместе или никак, только у `joint_position`, только при `angle_unit: rad`. Незаданные в каноническую форму не попадают — старые идентификаторы не меняются. Действие с коэффициентами порождает интерфейс `effort` и `joint_trajectory_controller` с `gains`: закон привода считается в стеке управления, а не сервоприводом симулятора |
| [ADR-0020](docs/decisions/0020-humanoid-joins-the-system-through-vendor-dds.md) | Мир комплекса — Gazebo. Гуманоид участвует в нём через DDS-интерфейс производителя: мост в сцене принимает `LowCmd` и отдаёт `LowState`, закон привода считается синхронно с физикой. Адаптер один — DDS поверх SDK, вне ядра, для моста, двойника MuJoCo и железа; меняется только конфигурация связи. MuJoCo — эталонный двойник и среда sim2sim, в сцену комплекса не входит. Порядок: адаптер против двойника MuJoCo, затем мост. План — `docs/plans/phase4-dds-bridge.md` |
| [ADR-0021](docs/decisions/0021-robot-ships-as-adapter-and-twin.md) | Пакет робота поставляет пару: адаптер на все среды и сторону двойника для пары «адаптер, бэкенд» — пятая точка расширения. Двойник объявляет процессы (значениями), род — владеющий физикой (сцена из одного робота) или мост в чужой физике — и требования к окружению; конфигурацию связи читает из `params` адаптера. Встроенный путь `ros2_control` в Gazebo — такой же двойник той же группы. `sim run` выбирает бэкенд через плагины; MuJoCo-бэкенд общий. Пакет G1 устроен как пакет производителя и импортирует только публичный API — проверяется тестом |
| [ADR-0022](docs/decisions/0022-vendor-dds-environment.md) | Версию DDS задаёт робот: CycloneDDS 0.10.2 — C-библиотека и обвязка из исходника, вне системных путей. CycloneDDS 0.11+ запрещён в окружении любого участника, встречающегося с роботом или двойником на 0.10.2: 0.10.2 падает при обнаружении участника 11.x — отказ до запуска. Процесс DDS-адаптера не загружает `rclpy`. Конфигурацию CycloneDDS строит транспорт, не `ChannelFactoryInitialize` SDK; от SDK — только IDL-типы и CRC. Конфигурация связи — домен, интерфейс, пиры — в `params` адаптера; локально — пир `127.0.0.1` на `lo` |
| [ADR-0023](docs/decisions/0023-reference-mujoco-twin.md) | Эталонный двойник MuJoCo — C++-симулятор `unitree_mujoco` производителя без правок, на закреплённых коммитах. Метка времени состояния в DDS-адаптере — `LowState.tick` (1 мс, время мира), не стенные часы. Двойник запускается аргументами (`-r -s -i -n`), `config.yaml` сборки не порождается. Пиры объявляет только сторона адаптера. Место и частота закона привода двойника — строка условий эксперимента |
| [ADR-0024](docs/decisions/0024-twin-protocol.md) | Протокол двойника двухслойный: общая часть в ядре (`Twin`: `adapter`, `backend`, `kind`), вклад в сцену — протоколом бэкенда (`GazeboTwin`: элементы описания, файлы, узлы запуска, имена управляющего слоя). Двойник ищется по объявленной паре, два на пару — ошибка. Генераторы не знают `ros2_control` по имени. Правила `twin.*` — только в мире установленного бэкенда и только для управляемых роботов. `sim run` берёт бэкенд из `sim_backends`, запускатель создаёт команда. Пакет робота импортирует только `PUBLIC_MODULES` |
| [ADR-0025](docs/decisions/0025-environment-requirements.md) | Требования к окружению — значения `Requirement` (виды `python`, `ros2`, `executable`, `variable`, реестр закрыт; версия по PEP 440; «нужно» или «запрещено» с причиной и подсказкой). Объявляет каждая сторона связи: член `requirements` у `ControlAdapter` и у `Twin`, без умолчания. Проверяется машина, не данные: не в `validate`; `env check` — сцена целиком, `sim run` — двойники до запуска, `run` — адаптер до подключения. Версия не определяется — нужное не выполнено, запрещённое найдено. «Находится» без импорта. Встроенные стороны объявляют выводом (`ADAPTER_PACKAGES`, `TWIN_PACKAGES`); узел запуска двойника из необъявленного пакета — ошибка генератора |
| [ADR-0026](docs/decisions/0026-refused-command-stops-the-robot.md) | Отказ адаптера в команде объявлен протоколом: `CommandRefusedError`, ничего не отправлено. Исполнитель на отказ — сначала `emergency_stop`, затем отмена навыка и `FAILURE` с причиной; на любое другое исключение — останов, затем исключение дальше; неудачный останов дописывается к причине, а не подменяет её. Отказ называет сустав, значение и пределы |
| [ADR-0027](docs/decisions/0027-g1-motor-slots-and-machine-identity.md) | Слоты моторов G1 — раскладка 29 приводов производителя в пакете робота, сустав находит слот по имени; пустой слот — `mode 0` и нули. Сверяется с порядком приводов MJCF, а не с таблицей производителя. `mode_machine` первого `LowState` называет тело: множество его суставов обязано равняться суставам контракта, иначе отказ при `connect`; неизвестное значение — отказ с числом |
| [ADR-0028](docs/decisions/0028-g1-emergency-stop-damps.md) | Аварийный останов DDS-адаптера G1 — одна команда демпфирования: `kp = 0`, `kd` из контракта, пустые слоты выключены. Не зависит от свежести позы, по пропаже которой срабатывает сторожевой таймер. Адаптер считается остановленным до отправки |
| [ADR-0029](docs/decisions/0029-g1-dds-channel.md) | Канал DDS — протокол пакета G1, не платформы: на границе значения `LowCommand` и `LowStateReading`, адаптер решает всё, канал только переводит и считает CRC. Настоящий канал — `cyclonedds` напрямую, импорт при открытии, процесс с `rclpy` отвергается. Связь — `params`: `domain` и `interface` обязательны, `peers` по желанию; XML собирается деревом |
| [ADR-0030](docs/decisions/0030-mujoco-backend-starts-the-twin.md) | Бэкенд `mujoco` в платформе запускает двойника, а не свой симулятор, и MuJoCo не импортирует. Вклад двойника — `MujocoTwin.processes(MujocoScene)`, значения `TwinProcess`; принимается только род «владеет физикой», участник один. Сцена — `world.file` сценария, вход; `check_scenario` получает путь сценария. Шаг физики не задаётся, а сверяется с `state_rate_hz`. Окно — решение двойника. Эластичная лента не используется: робот падает до первой команды — условие прогона (ADR-0018) |
| [ADR-0031](docs/decisions/0031-mjcf-is-a-second-description.md) | `description.mjcf` — второе описание робота, из репозитория и коммита двойника. `core.mjcf` читает стандартной библиотекой: включения, классы `<default>`, градусы в радианы. Правила `mjcf.*`: суставы, привод у каждого сустава контракта, пределы позиции в одну сторону, меши; расхождение URDF и MJCF — предупреждение с обоими числами. Мир MuJoCo: сцена задана, загружает описание профиля, шаг не медленнее состояния. Допуск 10⁻⁵ — по печатной точности MJCF. Порядок приводов — протокол робота, проверяется в пакете |
| [ADR-0032](docs/decisions/0032-a-skill-starts-inside-the-envelope.md) | Навык, строящий движение от измеренной позы, начинает с её проекции на `limits.joint_position` (`skills.base.admissible`): сустав за пределом — на ближайшую границу, перенесённые называются в журнале. Цель в рамке, рамка — прямоугольник, значит, весь разгон допустим. Адаптер по-прежнему отказывает всему вне рамки; допуска нет. Применено к `move_joints` и `hold` |
| [ADR-0033](docs/decisions/0033-gazebo-bridge-is-the-drive-firmware-twin.md) | Мост G1 в Gazebo — не костыль, а двойник прошивки приводов: контроллер `ros2_control` `unitree_g1_bridge/LowLevelBridge` в пакете робота, не общий (тип сообщения — свойство сборки). Закон считается в `update()` по последнему `LowCmd`, слот с `mode = 0` — без момента, до первой команды момента нет; `tick` — время мира в мс, `tau_est` — приказанный момент. Суставы, слоты, `mode_machine`, топики — параметрами из Python-стороны пакета, тест держит имена C++ и Python вместе. `generators.ros2_control` публичен. Путь `ros2_control` для G1 закрыт |
| [ADR-0034](docs/decisions/0034-gazebo-scene-dds-environment-and-names.md) | `GazeboTwin.environment(instance)` — переменные процессов мира; генератор пишет их `<set_env>` в начало запуска, разные значения одной переменной — отказ. Двойник G1 объявляет `rmw_cyclonedds_cpp`, домен и `CYCLONEDDS_URI` — ту же конфигурацию, что канал адаптера; с пирами `MaxAutoParticipantIndex` 32. Топики робота с фиксированными именами — в корне, один такой робот на домен; общий топик двух роботов сцены — отказ генератора. `rmw_cyclonedds_cpp` объявляет двойник, не `phase0.sh` |
| [ADR-0035](docs/decisions/0035-a-launch-is-stopped-as-at-a-terminal.md) | Мир Gazebo останавливается SIGINT запуску, как Ctrl+C: на SIGTERM `ros2 launch` отменяет себя и бросает детей (исходник `launch`, прогон этапа 5). `Process.interrupt()`, `stop_all(..., request=StopRequest)`; как просить — решает бэкенд (Gazebo — `INTERRUPT`, MuJoCo — `TERMINATE`). Просят один раз: переживший срок процесс убивается, а не просится другим сигналом |
| [ADR-0036](docs/decisions/0036-an-interrupt-must-be-deliverable.md) | Уточняет ADR-0035. `launch` слушает сигналы только через обработчики Python, а CPython не ставит обработчик SIGINT, унаследованного игнорируемым (фоновое задание скрипта). `SubprocessLauncher` на POSIX сбрасывает SIGINT ребёнка в `SIG_DFL` до `exec`; `sim run` явно превращает SIGINT и SIGTERM в одну остановку |
| [ADR-0037](docs/decisions/0037-a-world-is-a-process-group.md) | Заменяет адресата и ожидание ADR-0035. Мир — группа процессов: процесс запускателя на POSIX стартует в своей сессии; `interrupt()` — SIGINT группе, как терминал (посредник `/bin/sh -c` перед `gz sim` сигнал не передаёт); `wait()` ждёт опустения группы; `kill()` — SIGKILL группе; `terminate()` — по-прежнему одному процессу |
| [ADR-0038](docs/decisions/0038-the-executor-records-the-run.md) | Уточняет ADR-0003 на стороне исполнения. Запись прогона пишет исполнитель через внедряемый `Recorder`, по ходу прогона: каждое прочитанное состояние и каждую принятую адаптером команду. MCAP с JSON-каналами `/state` и `/command`, без ROS 2; `mcap` — группа `record`, импорт при открытии. `log_time` — часы исполнителя, `publish_time` — время мира (у команды — метка её состояния). Метаданные `run` с каноническим контрактом до первого такта, `result` при закрытии, прерванный — `interrupted`. Включается `run --record`; метрики — не часть записи |
| [ADR-0039](docs/decisions/0039-a-run-joins-the-world-in-its-environment.md) | `run` работает в окружении мира, к которому присоединяется: оно выводится из двойников сценария тем же путём, что пишется в запуск (ADR-0034), и применяется до проверки требований адаптера и `connect`. Переменная процесса с другим значением — отказ с обоими значениями. Двойник участника не находится — окружение не выводится: отказ, в сухом прогоне — строка плана. План печатает окружение |
| [ADR-0040](docs/decisions/0040-phase6-proves-the-pipeline-on-the-arm-first.md) | Уточняет ADR-0005 п. 1 — порядок, не объём. Фаза 6 — две части: `arm6` проводит конвейер целиком (Isaac → ONNX + контракт → `LearnedSkill` → Gazebo через `ros2_control`), G1 — вторая реализация на задаче ADR-0005 п. 1; фаза закрывается после обеих. Порог ADR-0005 — до кода бэкенда обучения: суррогатом, затем на задачах `arm6` и G1. Задача `arm6` — ради конвейера, это пишется открыто. До кода части G1 — решение о балансе в симуляции. План — `docs/plans/phase6-learned-skill.md` |

## Правила кода

**Имя платформы нигде не пишется литералом.** Единственная точка правды —
`src/heron/core/branding.py`. Ни в сообщениях CLI, ни в путях, ни в переменных окружения,
ни в поиске плагинов. В схемах данных имени нет вообще: только `schema_version`.
Имена топиков и узлов ROS 2 строятся от идентификатора робота. Правило действует
с первого коммита — см. раздел 17.

**Стек** (раздел 11): Python 3.11+, pydantic + YAML со строгими схемами, Typer для CLI,
uv для зависимостей, ROS 2 Jazzy, Gazebo Harmonic, MuJoCo, Isaac Lab 2.3, rsl_rl,
Foxglove и RViz для визуализации, файлы + JSON для хранилища, Docker Compose.
Своего дашборда, MLflow и Kubernetes не пишем.

**Ядро ставится без вендорских зависимостей.** Всё вендорское — в `examples/` и
опциональных группах зависимостей, подключается через точки входа Python.

**Расширение — только через пять точек** (раздел 5): четыре протокола `ControlAdapter`,
`Skill`, `SimBackend`, `TrainBackend` и сторона двойника (ADR-0021). Новая точка
расширения — это решение, а не правка.

**Запрещены костыли** — механизмы, существующие только чтобы обойти неудачный выбор.
Если обходной путь кажется нужным, ошибка выше по течению: её и надо найти.
