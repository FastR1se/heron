# unitree-g1

Пакет робота Unitree G1, устроенный так, будто его прислал производитель (ADR-0021): отдельный
дистрибутив, находится платформой через точки входа, импортирует из неё только публичный API.

| Точка входа | Что это | Этап плана фазы 4 |
|---|---|---|
| `adapters: unitree_g1_dds` | DDS-адаптер: один на двойник MuJoCo, мост в Gazebo и железо | 3 |
| `twins: unitree_g1_mujoco` | двойник MuJoCo: `unitree_mujoco` производителя без правок, род «владеет физикой» | 4 |
| двойник Gazebo | мост `ros2_control`, род «мост» | 5 |

## Установка

```bash
uv pip install -e examples/plugins/unitree_g1
```

Этого достаточно для тестов: всё, что решает адаптер, проверяется на записывающем канале. Живой
связи нужны ещё CycloneDDS 0.10.2 и SDK производителя — в процессе без `rclpy` (ADR-0022). Что
именно не хватает, называет `env check <сценарий>`.

## Конфигурация связи

Единственное, что отличает двойник от железа, — `params` адаптера в профиле (ADR-0029):

```yaml
adapters:
  sim.mujoco:
    plugin: unitree_g1_dds
    params: {domain: 1, interface: lo, peers: [127.0.0.1]}
```

| Ключ | Обязателен | Смысл |
|---|---|---|
| `domain` | да | домен DDS; у двойника производителя по умолчанию 1, у робота 0 |
| `interface` | да | сетевой интерфейс |
| `peers` | нет | адреса одноадресного обнаружения; непустой список выключает мультикаст |
| `link_timeout` | нет | сколько ждать первого `LowState`, с (10) |
| `poll_timeout` | нет | сколько ждать состояния в одном такте, с (0.1) |

## Двойник MuJoCo

`sim run examples/scenarios/humanoid_mujoco.yaml` запускает `unitree_mujoco -r g1 -s <сцена> -i <домен>
-n <интерфейс>`: сцена — `world.file` сценария, домен и интерфейс — из `params` адаптера (ADR-0030).
Пиры не передаются: двойнику их не задать, достаточно стороны адаптера (ADR-0023, п. 3).

| Требование | Зачем |
|---|---|
| программа `unitree_mujoco` на `PATH` | сборка `unitree_mujoco/simulate` на коммитах ADR-0023 |
| переменная `DISPLAY` | окно GLFW обязательно, безголового режима нет |

До запуска двойник отказывает, если мир просят без окна или если сцена — для другого тела: двойник
выводит `mode_machine` из имени файла сцены, и адаптер отказал бы уже при подключении.

Робот падает сразу после запуска мира: до первой команды момента нет, а эластичная лента выключена в
`config.yaml` производителя. Это условие прогона (ADR-0018), а не дефект.

## Что адаптер решает сам

- **Слоты** — раскладка 29 приводов производителя, сустав находит слот по имени; пустые слоты
  выключены (ADR-0027).
- **Тело на связи** — `mode_machine` первого `LowState` сверяется с суставами контракта; не то тело —
  отказ при подключении (ADR-0027).
- **Закон привода** — `kp`, `kd` из контракта в каждой команде (ADR-0019).
- **Метка времени** — `LowState.tick`, миллисекунды мира (ADR-0023).
- **Аварийный останов** — демпфирование: `kp = 0`, `kd` из контракта (ADR-0028).
