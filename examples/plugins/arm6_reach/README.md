# arm6_reach — задача обучения примера

Шестая точка расширения платформы (ADR-0044) на самом маленьком примере: пакет,
точка входа, сцена. Ни одного файла ядра.

Задача — привести суставы манипулятора `arm6` в заданную позу и удержать её.
Выбрана ради конвейера, а не ради трудности обучения; так и написано в
[ADR-0040](../../../docs/decisions/0040-phase6-proves-the-pipeline-on-the-arm-first.md).

## Что задача объявляет

| Член | Значение | Откуда |
|---|---|---|
| `backend` | `isaaclab` | бэкенд, в словаре которого написаны награды |
| `spec` | навык `arm6_reach`, `arm.joint_position`, `dof >= 6` | уходит в манифест артефакта (ADR-0046) |
| `completion` | допуск 0.05 рад, выдержка 0.2 с, горизонт 4 с | один допуск в двух мирах (ADR-0043) |
| `goal_range` | поза отсчёта ± 0.5 рад | внутри множества целей действия |
| `rewards` | слежение, точное слежение, штрафы за скорость и рывок | награду пишет человек |
| `terminations` | только горизонт | эпизод не обрывается на успехе |
| `events` | сброс — поза отсчёта ± 0.9 рад | накрывает нулевую позу мира исполнения |

**Чего задача объявить не может:** действие, наблюдение, частоты и привод. Их
задаёт контракт робота, и членов, через которые их можно изменить, у протокола
нет. Именно поэтому утверждение «представление данных одно в обоих мирах»
проверяемо, а не желаемо.

## Установка и проверка

```bash
pip install -e examples/plugins/arm6_reach
heron task list
heron train run examples/scenarios/arm6_train.yaml --dry-run \
    --registry examples/robots
```

Сухой прогон печатает выведенную среду — частоты, отображение действия, состав
наблюдения, коэффициенты привода — и команду, которая будет выполнена. Ничего
из этого не требует ни GPU, ни симулятора.

## Обучение

```bash
heron train run examples/scenarios/arm6_train.yaml \
    --registry examples/robots --envs 512 --iterations 1000
```

В окружении обучения: `isaaclab`, `isaacsim` и `rsl_rl` нужны, `rclpy` запрещён
(ADR-0025, ADR-0003). Проверяются до запуска — `heron train env <сцена>`.
