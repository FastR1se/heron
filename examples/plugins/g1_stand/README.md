# g1_stand — G1 учится стоять

Задача обучения ADR-0075: G1 тела 6 (`g1_29dof_lock_waist_rev_1_0`, `mode_machine = 6`) на
свободной базе держит стойку и не падает от толчков. Пакет, точка входа, сцена — ни одного файла
ядра.

Держит робота только политика. Встроенного контроллера баланса в мирах платформы нет, крепления
(как у `g1_upper_reach`, ADR-0063) тоже: описание производителя без звена `world`. Корпус политика
чувствует через IMU таза (ADR-0076).

## Что задача объявляет

| Член | Значение | Откуда |
|---|---|---|
| `backend` | `isaaclab` | бэкенд, в словаре которого написаны награды |
| `spec` | навык `g1_stand`, `arm.joint_position`, `dof == 27` | уходит в манифест артефакта (ADR-0046) |
| `completion` | допуск 0.25 рад по худшему суставу, выдержка 10 с, горизонт 20 с | один допуск в двух мирах (ADR-0043) |
| `goal_range` | ровно `default_pose` контракта — поза стойки | цель — стойка, диапазон нулевой ширины |
| `rewards` | живой, прямой, на месте, в позе; штрафы за падение, момент, ускорение, рывок | награду пишет человек |
| `terminations` | горизонт; таз ниже 0.5 м; наклон больше 0.8 рад | падение кончает эпизод |
| `events` | трение и груз таза — при старте; поза ± 0.1 рад, место ± 0.5 м, любое рыскание — при сбросе; толчок 0.5 м/с раз в 5–10 с | |
| `agent` | сеть 256×128×128, остальное — бэкенда | 114 входов, 27 выходов |

**Чего задача объявить не может:** действие, наблюдение, частоты, привод — контракт; высота
появления — `pose` сценария (ADR-0077).

**Что задача знает о роботе:** имя таза и высоту, ниже которой таз упавшего робота. Это знание
пакета, а не ядра.

## Установка и проверка

```bash
python examples/robots/g1_29dof_lock_waist_rev_1_0/fetch_description.py
uv pip install --no-deps -e examples/plugins/g1_stand
heron task list
heron train run examples/scenarios/g1_stand_train.yaml --registry examples/robots --dry-run
```

Сухой прогон печатает выведенную среду — физика 500 Гц, политика 50 Гц, decimation 10, база
свободна и появляется в `[0, 0, 0.8]`, действие шириной 27, наблюдение шириной 114 — и команду
процесса. Ни GPU, ни симулятор для этого не нужны.

## Обучение

На Ubuntu, в окружении обучения (`source scripts/activate.sh train`):

```bash
heron train run examples/scenarios/g1_stand_train.yaml --registry examples/robots \
    --envs 1024 --iterations 3000
```

Порог ADR-0005 (≥ 512 сред, VRAM ≤ 7 ГБ, RAM ≤ 13 ГБ, ≤ 6 ч) — условие прогона; числа — в карточку
эксперимента.

## Исполнение

Навык связывается в профиле одной строкой (`skills: [..., {g1_stand: g1_stand@<id>}]`, ADR-0046) и
исполняется `LearnedSkill`. Адаптер G1 подаёт IMU из `LowState.imu_state`, мост Gazebo его
заполняет (ADR-0076). **Прогон в Gazebo ещё не готов:** до первой команды мост не даёт момента, и
свободный G1 падает раньше, чем подключится `run`; держатель на время запуска — отдельное решение
(ADR-0075, «Последствия»).
