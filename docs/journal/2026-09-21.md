# Журнал сессии 2026-09-21

## Задача

Профиль робота из готового URDF: заготовка `profile new --from-urdf` (ADR-0074).
Сделанным считается: заготовка по настоящему описанию проходит `validate` без ошибок в обоих
классах связи, тесты зелёные.

## Сделано

- Вопрос пользователя «генерировать профиль из URDF» разобран до кода: из описания достоверно
  выводятся только суставы и их пределы; возможности, класс связи, частоты, наблюдение,
  действие, `kp`/`kd`, ускорение, адаптеры — нет. Вывод при каждой загрузке отвергнут: правила
  `urdf.*` стали бы тождественно истинными, а правка описания молча меняла бы `contract_id`.
  Решение — однократная заготовка, карточка `docs/decisions/0074-profile-stub-from-description.md`.
- `core.urdf`: `UrdfJoint.mimic` — имя ведущего сустава; правила валидатора его не читают.
- `cli/new_robot.py`: `write_stub(..., urdf=)` и `profile new --from-urdf <файл>`.
  `joint_order` — управляемые суставы без `<mimic>` в порядке документа; `limits.joint_position`,
  `joint_velocity`, `joint_torque` (если `effort` у всех) — из описания, числа кратчайшей
  обратимой формой. Описание не копируется: путь относительно профиля. Неуказанное в описании —
  плейсхолдер с TODO по имени сустава. `--dof` вместе с `--from-urdf` — отказ.
- Потоковая заготовка по описанию отображает `clip [-1, 1]` на рамку: `default_pose` — середина,
  `scale` — половина диапазона, `offset: default_pose` (ADR-0074, п. 8).
- Тесты: `tests/test_urdf.py` (mimic), `tests/test_cli.py` (заготовка по описанию валидна в обоих
  режимах, ведомый и неподвижные суставы вне контракта, TODO по имени, цели действия в рамке,
  отказы: `--dof`, `.xacro`, нет файла, нет управляемых суставов). Полный прогон: 794 прошло,
  14 пропущено; ruff и mypy чистые.
- Проверено руками на `g1_29dof_lock_waist_with_hand_rev_1_0.urdf` (41 управляемый сустав):
  `validate` — 0 ошибок в `streaming` и `command`, 3 ожидаемых предупреждения
  (`adapter.plugin_not_installed`, `urdf.collision_mesh_heavy` — 525 372 треугольника,
  `urdf.name_differs`).

## Проблемы и тупики

- **Первая заготовка по URDF G1 была невалидна.** Потоковый шаблон ADR-0056 пишет
  `clip: [-1.0, 1.0]` без масштаба и смещения — цели `[-1, 1]` рад. На скелете с пределами
  `±3.14` это проходило; на настоящей рамке G1 валидатор дал `contract.action_outside_limits` в
  20 суставах из 41 (колено `[-0.087267, 2.8798]`, голеностоп `±0.2618`, пальцы). Скелет
  маскировал несогласованность шаблона: пределы-заглушки были подобраны так, что `clip` в них
  помещался. Рассматривал убрать `clip` (правило тогда молчит) — отвергнуто: цели политики
  становятся неограниченными. Решено отображением на рамку (п. 8 карточки).
- **Округление при отображении.** `(lo+hi)/2 + (hi-lo)/2` может превысить `hi` на ulp, а правило
  сверяет суммы строго. Половина диапазона уменьшается `math.nextafter`, пока сумма не ляжет в
  рамку; тест сверяет `action_targets()` с рамкой для каждого сустава.
- Heredoc в Git Bash снова оборвался на многострочном скрипте правки (кавычки внутри) — правки
  применены скриптами из файлов, как записано в памяти.

## Наблюдения

- `<mimic>` парсер раньше не читал вовсе: ведомый палец схвата считался управляемым и попал бы в
  `joint_order`. В `commandable` это не перенесено — изменило бы поведение
  `urdf.joint_not_commandable` и генератора `ros2_control` на принятых профилях; отложено в
  карточке как отдельное решение.
- Порядок суставов в документе производителя G1 (ноги, пояс, левая рука с кистью, правая) не
  совпадает с раскладкой слотов DDS — это нормально: слот находится по имени (ADR-0027), а
  порядок контракта подтверждает человек, о чём и пишет комментарий заготовки.
