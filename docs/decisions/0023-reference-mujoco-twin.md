# ADR-0023. Эталонный двойник MuJoCo — C++-симулятор производителя без правок

**Статус:** принято
**Дата:** 13.09.2026

## Контекст

ADR-0020 назначил двойник производителя `unitree_mujoco` известно-исправной второй стороной
связи и эталоном, с которым сверяется мост в Gazebo. У производителя две реализации двойника,
и этап 0 (журнал 13.09.2026, сессия 5, факт 0.3) показал, что они по-разному считают закон
привода и по-разному заполняют `LowState`. Выбор между ними задаёт источник метки времени в
адаптере (этап 3), поэтому делается до адаптера.

Сверено чтением исходников (сессия 7):

| Репозиторий | Коммит |
|---|---|
| `unitree_mujoco` | `1eb6642e3f3fdfb7fb13a9794fd6a2dd93ea0e7d` |
| `unitree_sdk2` (C++) | `9754cd153af3da471b0fe5f3aa535e426fb11db3` (20.08.2026) |
| `cyclonedds`, тег `0.10.2` | `9995905bce6c4cf9f740d6438bbf7fcfd1c83dfd` |
| `cyclonedds-cxx`, тег `0.10.2` | `2a372d2c4597faea54543b925755fa2d7cdd4232` |

**Python-двойник** (`simulate_python`):
- `tick`, `mode_machine`, `crc` не заполняет;
- закон привода считает один раз на приход `LowCmd`, момент держит до следующей команды;
- связь поднимает через `ChannelFactoryInitialize(домен, интерфейс)` SDK на Python, чей шаблон
  содержит блок `<Tracing>`, а на сборке 0.10.2 он роняет процесс (ADR-0022).

**C++-двойник** (`simulate`):
- `LowState.tick = round(mjData.time / 1 мс)` — время мира;
- `mode_machine` = 4, если в имени файла сцены есть «23», иначе 5;
- закон привода `tau + kp·(q* − q) + kd·(dq* − dq)` считает поток `RecurrentThread` с
  периодом 1000 мкс по настенным часам и по последней команде; в том же такте публикует
  `LowState`. Физика идёт своим потоком под мьютексом сцены, синхронизированным с настенными
  часами; поток моста пишет `ctrl` и читает `sensordata` без этого мьютекса;
- шаг физики — умолчание MuJoCo 0.002 с: в `g1_23dof.xml` и `scene_23dof.xml` нет `<option>`;
- CycloneDDS — собранная производителем 0.10.2 из `unitree_sdk2/thirdparty`;
- `ChannelFactory::Init(домен, интерфейс)` подставляет интерфейс в шаблон
  `<CycloneDDS><Domain Id="any"><General><Interfaces><NetworkInterface name="…"
  multicast="default"/>…` — без `<Tracing>` и без пиров (строка извлечена из
  `libunitree_sdk2.a`, реализация закрыта);
- непустая конфигурация в `cyclonedds-cxx` создаёт домен явно (`dds_create_domain`), а
  `CYCLONEDDS_URI` ядро 0.10.2 читает только при неявном создании домена
  (`dds_participant.c`), так что передать двойнику пиры окружением нельзя;
- ядро 0.10.2 на интерфейсе без мультикаста само выключает мультикаст и ставит индекс
  участника `auto` (`q_init.c`), то есть слушает обнаружение на известном одноадресном порту;
  получив SPDP по одноадресному каналу, добавляет адрес отправителя в свой набор обнаружения
  (`q_ddsi_discovery.c`, `maybe_add_pp_as_meta_to_as_disc`) и отвечает ему;
- аргументы: `-r` робот, `-s` сцена (абсолютный путь принимается как есть), `-i` домен,
  `-n` интерфейс, `-t` тип IDL; остальное — только из `config.yaml` рядом с каталогом сборки,
  где все ключи обязательны; эластичная лента — только оттуда, по умолчанию выключена;
- окно GLFW обязательно, безголового режима нет.

## Решение

**Эталонный двойник MuJoCo — C++-симулятор `unitree_mujoco/simulate` производителя, без
правок**, на закреплённых коммитах `unitree_mujoco` и `unitree_sdk2` из таблицы выше.

1. **Метка времени состояния в DDS-адаптере — `LowState.tick`, 1 мс на единицу.** Это время
   мира (ADR-0015): не изменилась метка — мир не шагнул, и сторожевой таймер прав. Стенные
   часы меткой не служат.
2. **Двойник запускается аргументами, а не порождённым конфигом:** `-r g1 -s <абсолютный путь
   к сцене> -i <домен> -n <интерфейс>`. Домен и интерфейс читаются из `params` адаптера
   (ADR-0021). `config.yaml` сборки остаётся файлом производителя.
3. **Пиры объявляет только сторона адаптера.** Двойник их принять не может (пункт «Контекст»),
   а на `lo` без мультикаста ядро 0.10.2 делает его достижимым по известному порту. Это
   выведено из исходников и подлежит проверке прогоном до кода адаптера.
4. **Сцена — `scene_23dof.xml` производителя под своим именем.** Имя файла несёт `mode_machine`
   двойника; копировать или переименовывать вход платформа не вправе и так (ADR-0009), здесь
   это ещё и условие правильного `mode_machine`.
5. **Где считается закон привода — условие эксперимента, а не свойство, принятое за
   идеал:** поток 1 кГц по настенным часам при шаге физики 500 Гц, без общей синхронизации с
   ним. Эксперимент этапа 6 записывает это строкой условий.

## Альтернативы

**Python-двойник без правок.** Ставится без сборки, но непригоден трижды: без `tick` сторожевой
таймер сработает через 0.5 с на исправной связи; закон привода на приход команды при
`command_rate_hz: 50` — PD на 50 Гц; канал SDK на нашей 0.10.2 падает на трассировке.
Отвергнуто.

**Python-двойник с правками** (`tick`, закон на шаге, своя конфигурация). Правка превращает
известно-исправную сторону в нашу непроверенную — ровно то, от чего ADR-0020 требует порядка
«сначала адаптер против готового двойника». Отвергнуто.

**C++-двойник с правками** (закон в шаге физики, пиры в конфигурации). Эталон стал бы ближе к
железу, но перестал бы быть эталоном производителя, а сверка мерила бы расхождение с нашей
редакцией. Отвергнуто; расхождение с железом измеряется, а не исправляется.

**Свой двойник MuJoCo.** Две непроверенные стороны одной связи. Отвергнуто.

**Python-двойник на `cyclonedds` 11.x.** Запрещено ADR-0022. Отвергнуто.

## Последствия

- Окружение пакета G1 включает сборку `unitree_sdk2` на C++, MuJoCo (README производителя
  называет 3.3.6) и `unitree_mujoco/simulate`. Объявляет это пакет G1 (ADR-0021).
- На машине три `libddsc`: 0.10.2 производителя внутри двойника, наша 0.10.2 для адаптера,
  0.10.5 из Jazzy. В одном процессе они не встречаются.
- Двойнику нужен дисплей: `sim run` с MuJoCo на машине без графической сессии не поднимется, в
  CI он не запускается. Проверяемо до запуска — требование окружения.
- `mode_machine` 4 ↔ 23 DoF известен только из двойника; сверка с железом — фаза 7.
- Чего это не доказывает. Что `tick` железа — тоже миллисекунды: исходников прошивки нет, а
  исполнителю важна только монотонность и шаг. Что пиры на одной стороне работают — проверка
  прогоном (пункт 3). Что гонка потока моста с потоком физики безвредна: она у производителя,
  и её цена входит в разрыв, который измеряет этап 6.
