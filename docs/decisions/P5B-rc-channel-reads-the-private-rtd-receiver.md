# ADR-P5B. Канал RC читает пакет RTD закрытым приёмником SDK закреплённой версии

**Статус:** принято; уточняет ADR-0053, п. 3, и применяет ADR-0050, п. 2 и 4
**Дата:** 19.09.2026

## Контекст

- ADR-0050: метка показания — время робота (`sec`, `nsec` пакета RTD), и поза, метка и фаза одного
  `RobotState` — из одного показания робота. ADR-0049: фаза RC выводится из `buff_fill`, `wp_cntr`,
  `motion_mode` и `safety`. ADR-0052, п. 4: применённая шкала читается из каждого пакета (`act_vel_scale`).
  ADR-0055: проба сравнивает `act_q` с `act_flange_x`. ADR-0053, п. 3: канал копирует нужные поля RTD одним
  проходом.
- Сверка с исходником API 1.4.1 при написании канала (этап 3): **открытого доступа к пакету RTD у SDK нет.**
  Открытые методы читают по одному полю, каждый из своего `get_data()`: `motion.get_actual_position`
  (`act_q`), `safety_status.get`, `controller_state.get`, `motion.mode.get`, `check_warning_status`,
  `check_waypoint_completion` (`buff_fill`). Ни один не отдаёт `sec`/`nsec`, `wp_cntr`, `act_vel_scale`,
  `act_flange_x`, `cycle_time`. Весь пакет — только у `RobotApi._rtd_receiver.get_data()`.
- Приёмный поток SDK пишет поля объекта `RTD` по одному, без замка (факт 0.38), и проверяет маркеры
  начала и конца пакета (`0x12`, `0x21`) только при подключении. Если чтение сокета оборвётся по сроку
  посреди пакета, прочитанная часть отбрасывается, а следующее чтение начинается со сдвигом — и все
  дальнейшие пакеты разбираются в мусор без единой ошибки.
- ADR-0053, п. 3 опирается на то, что приёмный поток «не отпускает GIL между полями». Точнее: CPython
  переключает потоки только в точках проверки (вызов, обратный переход цикла) и только по запросу потока,
  ждущего GIL дольше интервала переключения (5 мс). Цикл разбора SDK — шестьдесят присваиваний, микросекунды;
  прерваться посреди него он может, только если ОС остановит его там дольше интервала.
- Требование окружения (ADR-0025) уже закрепляет версию: `API ==1.4.1`.

## Решение

**1. Канал читает пакет через `RobotApi._rtd_receiver.get_data()`** — закрытый член SDK, но одной
закреплённой версии: требование `API ==1.4.1` не пускает адаптер к другой. При открытии канал проверяет, что
приёмник есть и у него есть `get_data`, и иначе отказывает с именем версии, по которой написан. Больше ничего
закрытого канал не трогает: управление — открытыми методами (`scale_setup`, `joint.add_new_waypoint`,
`mode.set`, `get_robot_info`, `set_confirm_position_callback`, `set_disconnection_callback`).

**2. Копия — одно выражение без вызовов.** Все восемнадцать полей загружаются в одном кортеже: в нём нет ни
вызова, ни обратного перехода, значит, у читающего потока нет точки, где он уступил бы GIL приёмному. Перевод
типов — после, над копией. Остаётся сторона писателя — условие ADR-0053, п. 3, теперь названное точно: разрыв
возможен, только если ОС остановит приёмный поток посреди разбора дольше интервала переключения.

**3. Каждое показание проверяет маркеры пакета.** Показание с маркерами не `0x12`/`0x21` отбрасывается и
пишется в журнал процесса: для исполнителя это молчание, и при затянувшемся сдвиге срабатывает сторожевой
таймер, а не навык, читающий мусор как позу.

**4. Новое показание — новая метка.** `poll` возвращает только показание, чья пара (`sec`, `nsec`) отличается от
прошлой, и ждёт его до срока (ADR-0016). Показание с той же меткой — не новое.

## Альтернативы

**Открытые методы, по одному полю.** Поза, статус и режим — из разных пакетов, метки времени нет вовсе,
счётчика точек нет: фаза не выводится (ADR-0049), свежесть меряется стенными часами (против ADR-0050, п. 2),
шкала не проверяется (против ADR-0052, п. 4). Отвергнуто.

**Разбирать поток RTD самим** (порт 29000, формат `STRUCT_FORMAT`). Полная согласованность и проверка каждого
пакета, но это повтор протокола производителя и второе соединение с RTD; ADR-0053 уже отверг его: версии и
совместимость проверяет SDK. Отвергнуто.

**Подменить объект `RTD` приёмника своим, с замком.** Вмешательство в закрытое устройство SDK глубже, чем
чтение: запись в чужой объект, чей код мы не контролируем. Отвергнуто.

**Попросить производителя открыть метод чтения пакета целиком.** Правильный путь, но не в сроки фазы.
Записывается как просьба к производителю в руководство и в журнал; при появлении такого метода — новая карточка,
заменяющая п. 1.

## Последствия

- `sdk.copy_rtd`, проверка маркеров, `poll` по метке; тесты — на заменителе `API`, написанном в тестах пакета,
  не на коде производителя.
- Переход на другую версию API — это правка пакета (требование, проверка приёмника, сверка по исходнику), а не
  обновление зависимости. Так и должно быть: адаптер написан по исходнику одной версии.
- Урок для руководства (критерий 10): до кода адаптера проверить, отдаёт ли SDK показание целиком и с меткой;
  если нет — назвать, через что читается, и закрепить версию.
- Проба этапа 4 пишет `cycle_time`, пары меток и маркеры: единица `cycle_time` (0.31) и монотонность меток
  (0.47) — оттуда. Сверка такта с `state_rate_hz` из ADR-0050 ждёт единицы поля: в исходнике и в руководстве её
  нет.
