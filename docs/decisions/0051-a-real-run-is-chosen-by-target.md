# ADR-0051. Прогон на железе выбирается целью, а не сценарием

**Статус:** принято; уточняет ADR-0039, применяет ADR-0002 к прогону
**Дата:** 16.09.2026

## Контекст

- Раздел 8, «Перенос на железо»: адаптер переключается с симуляционного на реальный, **та же миссия без
  правок**, затем сравнение метрик sim и real. Инвариант 3: между симуляцией и железом меняется только
  конфигурация адаптера.
- Ключ адаптера профиля — `real` или `sim.<бэкенд>` (`REAL_TARGET` в `core.models`). `run` выводит ключ из
  `world.backend` сценария; `--target` его заменяет. Сценария «на железе» в модели нет.
- ADR-0039: `run` применяет к процессу окружение мира, выведенное из двойников сценария, — чтобы связь нашла
  мир в его домене DDS. Сейчас это делается при любой цели. `run --target real` для сценария `humanoid`
  направил бы связь настоящего G1 в домен симулятора.
- Раздел 12: «Валидатор проверяет лимиты суставов, скоростей и рабочей зоны перед любым запуском на железе».
  Сейчас профиль без `limits` запускается на любой цели.
- Критерий 10 плана фазы 5: пользователь с API без симулятора доходит до железа.

## Решение

**1. Владельца физики прогона выбирает цель.** `sim.<бэкенд>` — мир сценария; `real` — действительность.
Блок `world` сценария описывает симулированный мир, `task` — миссию, одну для обеих целей. Имя `real` в
`world.backend` не вводится.

**2. Прогон на железе не применяет окружение мира.** Связь с настоящим роботом настраивают только `params`
адаптера `real`. План сухого прогона печатает `мир  действительность, окружение мира не применяется`.

**3. Сценарий проверяется целиком и при цели `real`.** Миссия, не проходящая проверку в своём симулированном
мире, на железо не идёт. У робота без симулятора производителя этот мир — `dummy` в командном режиме:
профиль объявляет `sim.dummy` рядом с `real`. Порядок «проверка в симуляции → перенос на железо» остаётся
свойством платформы, а не привычкой.

**4. Рамка для железа обязательна.** При цели `real` профиль без `limits.joint_position` или без
`limits.joint_velocity` — отказ до подключения с кодом `real.limits_missing` и списком недостающего.

**5. Команда `deploy` не вводится.** `run --target real` — перенос одного робота. Раздача миссии по
контейнерам многих роботов — дело координатора (раздел 4), и фаза 5 его не делает.

## Альтернативы

**`world.backend: real` в отдельном сценарии.** Миссия живёт в двух файлах, «та же миссия без правок» становится
«та же миссия, скопированная», а сравнение sim и real — сравнением двух документов, которые могли разойтись.
Плюс исключение в выводе ключа: `real`, а не `sim.real`. Отвергнуто.

**`run` по профилю без сценария.** У миссии нет документа: цель приходит строкой команды, проверка
сценария пропадает целиком. Отвергнуто.

**Проверять при цели `real` только профиль.** Позволило бы запускать на железе то, что ни разу не проходило
проверку в мире, — ровно тот порядок, против которого платформа. Отвергнуто.

**Окружение мира применять и на железе.** Ведёт связь настоящего робота в домен симулятора (контекст).
Отвергнуто.

## Последствия

- `cli.run`: окружение мира и конфликт переменных (ADR-0039) — только для `sim.*`; правило
  `real.limits_missing`; строка плана о мире. Сухой прогон при `real` по-прежнему ничего не подключает.
- Профиль RC5 объявляет два адаптера: `sim.dummy` с `control_mode: command` и `real` пакета. Сценарий фазы 5
  — `world.backend: dummy`.
- `sim run` и `gen` цели не принимают и не меняются: они строят мир, а у действительности строить нечего.
- Для G1 это исправление, а не новое: прогон на железе со сценарием `humanoid` больше не унаследует домен DDS
  симулятора.
