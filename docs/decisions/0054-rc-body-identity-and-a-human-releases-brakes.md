# ADR-0054. Адаптер RC удостоверяет тело по имени модели, тормоза снимает человек

**Статус:** принято; по образцу ADR-0027
**Дата:** 16.09.2026

## Контекст

- ADR-0027: адаптер G1 при `connect` сверяет тело, названное роботом, с контрактом, и отказывает при
  расхождении. Подключиться к другому телу и начать командовать им — худшая ошибка связи.
- RC: `get_robot_info()` в режиме `full` возвращает `robot_model` (пример из документации — `rc10b2`) и
  DH-параметры (0.7). DH — не калибровка тела, а таблица модели, выбранная регуляркой из имени (0.34).
  Число суставов в SDK — константа 6 (0.43).
- Переход контроллера в `run` (снятие тормозов) SDK делает `controller_state.set("run")`. На этом переходе
  SDK сверяет сохранённую позу с фактической: расхождение больше 5° по любому суставу вызывает обработчик
  подтверждения, по умолчанию — вопрос в терминале через `input()` (0.17, 0.41).
- При первом пуске руководство ввода в эксплуатацию снимает тормоза человеком в «Пульсе»: включение, запуск,
  щелчки тормозов, проверка кнопки (ввод, 5). API и «Пульс» не управляют роботом одновременно (0.5).
- Раздел 12: кобот — с физической кнопкой останова.

## Решение

**1. Тело удостоверяется по имени модели.** `params` адаптера `real` объявляют `model` — строку ровно в том
виде, в каком её возвращает контроллер. При `connect` в `full` адаптер сравнивает её с
`get_robot_info().robot_model` на равенство и отказывает, называя оба значения. Пустое имя от контроллера —
отказ. Число суставов SDK сверяется с `contract.dof`.

**2. DH-параметры не сверяются.** Это таблица модели, а не измерение тела: совпадение с описанием
доказывало бы только то, что описание списано с той же таблицы (ADR-0055).

**3. Адаптер не меняет состояние питания и тормозов.** Ни `on`, ни `run`, ни `off`. Контроллер не в `run` при
`connect` — отказ с подсказкой: перевести робота в рабочее состояние в «Пульсе» человеком у кнопки и
отключить «Пульс» от управления. Снятие тормозов остаётся действием человека, который видит робота.

**4. Подтверждение позиции — всегда отказ.** Канал ставит свой обработчик: он запоминает расхождения и
возвращает «не подтверждено». `connect` отказывает, называя сустав, фактический и сохранённый угол и порог.
Ни `input()`, ни автоматического согласия. При решении 3 SDK сам к подтверждению не придёт — обработчик
стоит, чтобы ни один путь внутри SDK не мог повиснуть на терминале или согласиться за человека.

## Альтернативы

**Сравнивать семейство модели регуляркой SDK** (`rc5` в `rc5b2`). Вывод следствия из имени; ADR-0001 выбирает
равенство. Первое настоящее значение даст проба 0.22, и профиль запишет его целиком. Отвергнуто.

**Сверять DH с описанием.** См. решение 2. Отвергнуто.

**Адаптер переводит контроллер в `run` сам.** Удобно для автоматического стенда, но снимает тормоза программой
при первом же прогоне нового кода. Если когда-нибудь понадобится — отдельной командой платформы с отдельной
карточкой, не побочным действием `connect`. Отвергнуто сейчас.

**Автоматическое подтверждение при малом расхождении**, как в примере производителя. Порог выбрал бы не тот,
кто видит робота; расхождение в 5° после сбоя питания — ровно то, что надо увидеть глазами. Отвергнуто.

## Последствия

- Профиль RC5: `adapters.real.params: {host: …, model: …}`; значение `model` — после пробы 0.22.
- Остаётся ли контроллер в `run`, когда «Пульс» отпустил управление, и примет ли тогда API `full` — факт 0.45.
  Если нет, решение 3 требует пересмотра новой карточкой, а не правкой этой.
- Записывающий канал пакета отдаёт `robot_model` и состояние контроллера: оба отказа проверяются без робота.
- Для руководства (критерий 10): удостоверение тела при `connect` и запрет адаптеру снимать тормоза — общая
  обязанность адаптера железа, не особенность RC.
