# ADR-0074. Заготовка профиля читает готовое описание

**Статус:** принято; дополняет ADR-0056
**Дата:** 21.09.2026

## Контекст

- Требование пользователя (21.09.2026): профиль робота порождать из URDF.
- `new-robot` (ADR-0056) пишет цепочку `joint0…jointN` с пределами `±3.14` и `1.0` рад/с и
  скелет описания. У кого описание уже есть (выгрузка CAD, модель производителя), тот
  переписывает `joint_order` и `limits` из URDF руками, сустав за суставом. RC5 — 6 суставов,
  G1 — 29; пределы G1 переносились из URDF вручную (журналы 2026-09-15, 2026-09-18), и
  первая сверка `urdf.*` нашла расхождение в пятом знаке (ADR-0031).
- Из описания достоверно выводится только часть профиля: имена и типы суставов, их пределы
  (`lower`/`upper`, `velocity`, `effort`), закрепление базы. Не выводятся: возможности
  (инвариант 7 — по дереву звеньев «рука» не угадывается), класс связи, частоты, наблюдение
  и действие, `kp`/`kd` (`<dynamics damping>` — трение модели, не коэффициент привода),
  предел ускорения (в URDF его нет), адаптеры, навыки.
- Описание — вход (ADR-0009), правила `urdf.*` сверяют с ним профиль. `joint_order` входит в
  `contract_id` (ADR-0004).
- Парсер `core.urdf` не читает `<mimic>`: ведомый сустав схвата выглядит управляемым.

## Решение

1. `profile new <имя> --from-urdf <файл>` строит заготовку по готовому описанию. Описание не
   копируется и не переписывается: `description.urdf` в профиле — путь к этому файлу
   относительно профиля (абсолютный, если относительного нет — другой диск). Скелет
   описания в этом случае не пишется. `--dof` с `--from-urdf` — отказ: число суставов
   задаёт описание.
2. Из описания берутся: `contract.joint_order` — управляемые суставы (`revolute`,
   `continuous`, `prismatic`) без `<mimic>`, в порядке документа; `limits.joint_position` —
   `lower`/`upper`; `limits.joint_velocity` — `velocity`; `limits.joint_torque` — `effort`,
   если он задан у всех суставов. Остальное пишется как в ADR-0056, с TODO.
3. Что описание не задаёт, помечается в профиле по имени сустава, а не заполняется молча:
   у `continuous` пределов позиции нет — пишется `±π` с TODO; нет `velocity` — `1.0` с TODO;
   предел ускорения командного класса — `2.0` с TODO «в описании нет».
4. Каждое взятое из описания поле помечено комментарием: пределы описания — механические,
   рамка профиля обязана быть не шире (раздел 12) и сужается человеком; порядок суставов
   входит в контракт и подтверждается человеком.
5. Вывод однократный. После заготовки профиль и описание — два независимых файла, и
   платформа их только сверяет (`urdf.*`). Команды «пересобрать профиль из описания» нет.
6. `UrdfJoint.mimic` — имя ведущего сустава или `None`. Правила валидатора его пока не
   читают: заготовка ведомые суставы в контракт не кладёт, а профиль, который положил их
   сам, валидатор принимает как раньше.
7. Описание без управляемых суставов, шаблон `.xacro`, нечитаемый файл, сустав с
   `lower >= upper` — отказ с кодом 2, ничего не создано.
8. Потоковая заготовка отображает `clip [-1, 1]` ровно на рамку описания (ADR-0041):
   `default_pose` — середина диапазона сустава, `scale` — половина, `offset: default_pose`,
   всё под TODO «замените на рабочую позу». Прежний `clip [-1, 1]` без масштаба на рамке
   G1 даёт `contract.action_outside_limits` в 20 суставах из 41 (колено
   `[-0.087, 2.88]`): заготовка была бы невалидной в день создания. Половина диапазона
   уменьшается на ulp, пока округление выносит цель за границу, — валидатор сверяет те же
   суммы точно. Командная заготовка действие не отображает, как и раньше.

## Альтернативы

**Профиль выводится из описания при каждой загрузке.** Правила `urdf.*` становятся
тождественно истинными — рассогласование профиля с описанием перестаёт быть обнаружимым
(инвариант 6). Правка описания молча меняет `joint_order`, а с ним `contract_id` и
совместимость всех политик — без `revision` (ADR-0004). Пределы описания — механика,
рамка профиля — безопасность; одно поле для двух величин. Отвергнуто.

**Команда «обновить профиль из описания» поверх существующего профиля.** Слияние двух
источников: чьё значение побеждает, когда человек сузил рамку, а описание расширило
механику? Любой ответ — второй источник правды для `limits`. Расхождение и так печатает
валидатор с обоими числами. Отвергнуто.

**Копировать описание в каталог заготовки.** Относительные ссылки на меши ломаются при
переносе, `package://` — тем более; копия расходится с оригиналом при следующей выгрузке
CAD. Описание — вход, а не выход (ADR-0009). Отвергнуто.

**Выводить `capabilities` и `control_mode` по устройству дерева.** Угадывание типа робота
по звеньям — ровно то, что запрещает инвариант 7. Отвергнуто.

**Потоковая заготовка без `clip`.** Правило ADR-0041 тогда молчит, но цели политики ничем
не ограничены, и заготовка учит писать контракт без рамки действия. Отвергнуто.

**Считать `<mimic>` неуправляемым в `UrdfJoint.commandable`.** Меняет поведение правил
`urdf.joint_not_commandable` и генератора `ros2_control` для уже принятых профилей — это
отдельное решение с проверкой на мирах, а не побочный эффект заготовки. Отложено.

## Последствия

- `write_stub` получает `urdf`; `Stub.description` — `None`, когда описание не создавалось.
- Тесты: заготовка по описанию проходит `validate` без ошибок в обоих классах связи;
  `mimic` и `fixed` не попадают в `joint_order`; `continuous` получает `±π` и TODO с именем;
  `--dof` вместе с `--from-urdf`, `.xacro` и описание без управляемых суставов — код 2.
- Числа из описания переносятся без округления (кратчайшее обратимое представление), чтобы
  первая же сверка `urdf.*` не нашла расхождения в последнем знаке.
- Руководство пользователя — по просьбе пользователя, не в этом изменении.
