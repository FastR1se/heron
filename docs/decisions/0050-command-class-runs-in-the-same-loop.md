# ADR-0050. Командный класс исполняется тем же циклом

**Статус:** принято; уточняет ADR-0015 для командного класса
**Дата:** 16.09.2026

## Контекст

- ADR-0015: исполнитель ведёт темп по `command_rate_hz`, сторожевой таймер — по `state_rate_hz` (десять
  периодов, не менее 0.5 с), свежесть меряется стенными часами, время мира — метками адаптера. «Цикл один».
- У командного робота между командами секунды: `goto_joints` (ADR-0049) отдаёт одну команду на движение и
  дальше только читает. `rest_arm` объявляет `command_rate_hz: 2`, `state_rate_hz: 20`; правило
  `contract.command_rate_suspicious` предупреждает о командном режиме выше 20 Гц.
- У RC5 состояние приходит пакетами RTD с меткой контроллера `sec`/`nsec` (0.30) и фактическим тактом ядра
  `cycle_time` (0.31). Порядок полей снимка не защищён замком SDK (0.38).
- Движение исполняет контроллер без участия связи. Что он делает при обрыве управляющего сокета, неизвестно
  (0.44).

## Решение

**1. Цикл не меняется.** В командном классе период `1/command_rate_hz` — период решения: прочитать состояние,
дать навыку такт. Команда уходит, только когда навык её отдаёт. Второй цикл, ждущий события завершения, не
вводится.

**2. `state_rate_hz` командного робота — частота, с которой робот публикует состояние,** а не частота опроса.
Сторожевой таймер считается от неё, как в ADR-0015. Метка состояния — время робота, если оно у робота есть
(у RC5: `sec + nsec·10⁻⁹`); стенные часы — только для свежести.

**3. В командном классе сторожевой таймер замечает, а не защищает.** Пропажа состояния обнаруживается не
позже одного периода опроса после порога. Останов по ней на мёртвой связи не доставить, а движение контроллер
ведёт сам. Защита при обрыве связи — свойство контроллера (0.44), и карточка аварийного останова пишется после
пробы.

**4. Одно показание — одно чтение робота.** Поза, скорость, метка и фаза движения одного `RobotState` обязаны
относиться к одному показанию робота. Как это обеспечить у RC5 — ADR-0053.

## Альтернативы

**Отдельный исполнитель командного класса, ждущий завершения событием.** Два цикла с двумя сторожевыми
таймерами и двумя путями отказа (ADR-0026) — то, от чего ADR-0015 ушёл, сведя `run_skill` к тому же циклу с
неидущими часами. Отвергнуто.

**Опрос на `state_rate_hz` в командном классе.** Темп зависел бы от режима, хотя контракт уже называет, как
часто решается о роботе. Опрос 500 Гц ради движения в секунды — нагрузка без пользы. Отвергнуто.

**Метка стенными часами при чтении.** Годится, когда у робота нет своих часов. У RC5 есть; метка чтения
смешала бы время мира с задержками процесса (ADR-0015). Отвергнуто для роботов с меткой.

## Последствия

- Изменений кода исполнителя нет. Проверка — `goto_joints` на `dummy` в командном режиме.
- Время реакции навыка на конец движения — до одного периода: у `rest_arm` 0.5 с. Для миссии, которой этого
  мало, `command_rate_hz` поднимается в профиле; предупреждение выше 20 Гц остаётся.
- Монотонность меток RC5 не доказана (0.47). Невозрастающая метка для исполнителя — не новое показание; если
  метки прыгают назад, это проявится срабатыванием сторожевого таймера, а не тихой ошибкой.
- Пакет RC сверяет при `connect` такт ядра с объявленной частотой: `cycle_time` больше `1/state_rate_hz` —
  отказ с обоими числами. Сравнение одностороннее, допуска нет: робот, публикующий чаще объявленного, таймер
  не обманывает, реже — обманывает.
