# ADR-0047. `LearnedSkill`: сверка до подключения, один такт — одно отображение

**Статус:** принято; реализует раздел 5 архитектуры по ADR-0041–0043, ADR-0046
**Дата:** 16.09.2026

## Контекст

- Раздел 5: `LearnedSkill` — единственная реализация `Skill` для политик в ядре. Этап 5 плана требует, чтобы
  внесённые расхождения артефакта были отказами **до подключения**.
- ONNX производителя: вход `obs` `[1, N]`, выход `actions` `[1, M]`, `float32`, оси не динамические.
  Паритет TorchScript и `onnxruntime` — 1.91·10⁻⁶ (эксперимент 0002). Группа `onnx` в `pyproject.toml` уже
  есть. `onnxruntime` 1.30.0 для Python 3.12 окружения исполнения ставится.
- `RobotState` несёт положения, скорости и моменты суставов и позу базы, но не скорости базы.
- Типы ядра — кортежи; числовой стек в ядро не тянется.

## Решение

**1. `skills/learned.py`, одна реализация.** Объявление (`SkillSpec`) строится из манифеста, под именем
привязки в профиле. Проверка совместимости с роботом и связью — та же, что у навыка кодом.

**2. Загрузка и сверка — до требований адаптера и `connect`.** Коды:

- `policy.artifact_inconsistent`, `policy.manifest_inconsistent`;
- различие контрактов по полям (существующие коды);
- `policy.capabilities_missing`;
- `policy.onnx_signature_mismatch` — не один вход `[1, observation_size]` `float32` или не один выход
  `[1, action_size]`;
- `policy.observation_unavailable` — терм, которого нет в `RobotState` (скорости базы);
- `policy.action_unsupported` — действие не `joint_position` (в этой фазе);
- `policy.completion_undefined` (ADR-0043).

**3. `onnxruntime` — группа `onnx`,** импорт при загрузке, провайдер CPU, один поток. Без группы — ошибка с её
именем.

**4. Старт:** цель по ADR-0043.

**5. Такт:**

1. Наблюдение по термам контракта из состояния, цели и прошлого выхода.
2. Выход сети, клип, отображение (ADR-0041).
3. Команда `joint_position`; клипнутый выход запоминается как `previous_action`.
4. Проверка завершения по состоянию этого такта.

Длина вектора состояния не та — `FAILURE` с записью в журнал навыка.

**6. Отказ адаптера** обрабатывается по ADR-0026 без изменений. ADR-0032 не применяется: политика не командует
измеренной позой, а цели лежат в рамке по построению (ADR-0041).

**7. Наибольшее время вывода сети** записывается в журнал навыка при завершении.

**8. `numpy`** — только внутри навыка. Вход и выход ядра — кортежи.

## Альтернативы

**`LearnedSkill` пакетом вне ядра.** Политики разных роботов — данные одной реализации. Отвергнуто.

**Сверка на первом такте.** Робот к этому моменту уже подключён. Отвергнуто.

**TorchScript на исполнении.** Тяжёлая зависимость в окружении исполнения, а паритет ONNX уже измерен.
Отвергнуто.

**Несколько потоков `onnxruntime`.** Сеть 64×64, и разброс времени такта важнее пропускной способности.
Отвергнуто.

**Проекция цели на рамку.** См. ADR-0041. Отвергнуто.

## Последствия

- Тесты на `dummy`: крошечная сеть ONNX строится пакетом `onnx` (группа `dev`); каждое нормативное поле
  отклоняется своим кодом до первого такта.
- Время вывода — строка эксперимента этапа 6.
