# ADR-0059. Тело G1 по `mode_machine` называет таблица описаний производителя

**Статус:** принято; уточняет источник значений ADR-0027
**Дата:** 19.09.2026

## Контекст

- ADR-0027: `mode_machine` первого `LowState` называет тело, множество его суставов обязано совпасть с
  суставами контракта. Значения 4 и 5 взяты из C++-двойника. Там же сказано: «что публикует железо, из
  исходников не видно», и новое значение добавляется как факт.
- 18.09.2026 настоящий G1 пользователя сообщил `mode_machine = 6`. Значение добавили в `slots.py` как
  «обнаруженное эмпирически»: скрипт показал 27 активных слотов, у талии пусты крен и тангаж. Профиль
  `g1_27dof` собрали на описании `g1_29dof_lock_waist.urdf` и на MJCF 29 DoF, валидатор выдал
  `urdf.name_differs` и `mjcf.differs_from_urdf` ([журнал](../journal/2026-09-18.md), сессии 25–26).
- Утверждение ADR-0027 неверно. README каталога `robots/g1_description` в `unitree_ros` — на коммите
  `7d6075f`, который платформа уже загружает, — содержит таблицу «описание → `mode_machine`»:
  4 — `g1_23dof_rev_1_0`, 5 — `g1_29dof_rev_1_0`, **6 — `g1_29dof_lock_waist_rev_1_0`** и ещё
  полтора десятка значений. Устаревший `g1_29dof_lock_waist` соответствует значению 3. Он отличается
  редуктором крена бедра: 88 Н·м и 32 рад/с против 139 и 20. Позиционные пределы у них совпадают.
- В `g1_29dof_lock_waist_rev_1_0.urdf` крен и тангаж талии — `fixed`, подвижных суставов 27. Это то
  самое «описание на 27 DoF», которого, по журналу, у производителя нет.
- Для этого тела нет двойника MuJoCo. Двойник производителя загружает сцену на 23 или 29 степеней
  свободы и сообщает 4 или 5, а MJCF `unitree_ros` объявляет приводы подряд, не по слотам
  (ADR-0031).

## Решение

1. **Значения `MACHINES` берутся из таблицы производителя.** Тело значения — множество подвижных
   суставов описания, которое таблица для него называет. Тест пакета читает README на закреплённом коммите
   и сверяет и номер, и множество суставов для каждого известного значения. Если описание не загружено,
   тест пропускается.
2. **В `MACHINES` — только значения, которые сообщал робот или двойник:** 4, 5, 6. Незнакомое значение
   по-прежнему отвергается с его номером и добавляется из таблицы, когда его сообщит робот. Угадывать не
   нужно: ответ лежит в таблице.
3. **Профиль исполнения называется по описанию** и стоит на нём: `g1_29dof_lock_waist_rev_1_0`. Тогда
   `urdf.name_differs` снова означает ошибку, а не шум.
4. **Нет двойника — нет мира.** У профиля нет `description.mjcf` и `sim.mujoco`: связь с двойником 29 DoF
   отвергла бы тело из 27 суставов при `connect`. Остаются `dummy`, Gazebo (мост получает
   `mode_machine: 6` из набора суставов, ADR-0033) и железо.

## Альтернативы

**Эмпирическое значение без источника**, как записано 18.09. Результат тот же, но непроверяемый: в
репозитории нет дампа, по которому решали. И «27 DoF» — слово платформы, которого у производителя нет.
Отвергнуто.

**Перенести в `MACHINES` всю таблицу сразу.** Значения 10–18 — исполнения с другими приводами запястий и
редукторами бедра. Множество суставов у них то же, а пределы моментов другие, и сверка тела их не
различит. Добавлять тела, которых ни один робот платформе не сообщал, — ровно то угадывание, от которого
предостерегает ADR-0027. Отвергнуто: значение приходит из таблицы тогда, когда его сообщит робот.

**Оставить устаревшее описание `g1_29dof_lock_waist`.** Позиционные пределы совпадают, но описание
принадлежит другому исполнению (значение 3), и предел момента крена бедра в нём чужой. Отвергнуто.

## Последствия

- `slots.py`: `BODY_29DOF_LOCK_WAIST`, `MACHINES[6]`, источник значений в документации модуля. Тест
  `test_each_mode_machine_is_the_body_of_the_description_the_vendor_names_for_it`.
- Профиль `g1_27dof` переименован в `g1_29dof_lock_waist_rev_1_0`. В сценарии пользователя меняется
  одна строка `profile:`. `fetch_description.py` загружает только URDF и README.
- `g1_23dof` стоит на устаревшем `g1_23dof.urdf` (значение 1), а двойник и железо сообщают 4, то есть
  `g1_23dof_rev_1_0`. Различие то же — крен бедра. Для симуляции оно не важно: двойник считает по своему
  MJCF. Переход на `rev_1_0` меняет вход опорного профиля фазы 4, поэтому это отдельное решение, не
  попутная правка.
- В инструкции `g1-on-hardware.md` исполнение выбирается по таблице: номер виден в приложении
  производителя (Device → Data → Robot → Machine Type).
