# ADR-P8F. Запись прогона комплекса — каталог: план, события по ходу, итог и записи задач

**Статус:** принято; уточняет ADR-0038 для миссии
**Дата:** 19.09.2026

## Контекст

- ADR-0038: запись прогона одного робота пишет исполнитель по ходу, через внедряемый `Recorder`, в MCAP.
  Метаданные `run` описывают один навык и одну цель; прерванный прогон читается и помечен
  `interrupted`.
- В миссии состояния роботов остаются в их процессах (ADR-P8D). У G1 это 500 Гц, у манипулятора
  100 Гц.
- Координатор видит только события: задача начата, задача окончена, робот готов, связь потеряна.
- `mcap` — необязательная группа. Координатор обязан работать и без неё.

## Решение

1. **Прогон миссии — каталог.** По умолчанию `data_home()/missions/<миссия>/<время UTC>/`, иначе `--into`.
2. **`plan.json`** пишется до запуска роботов (ADR-P8D).
3. **`events.jsonl`** — события координатора, по строке на событие, дописываются в момент события. У каждой
   строки два времени: секунды часов координатора от начала миссии и UTC в наносекундах.
4. **`result.json`** пишется в конце: состояние миссии и каждой задачи с причиной, тактами и числом
   команд. Файла нет — прогон прерван, а события до обрыва на месте.
5. **`--record`:** процесс каждого робота пишет MCAP на каждую свою задачу, `<задача>.mcap`, в формате
   ADR-0038 без изменений. Метаданные `run` дополнены полями `mission`, `task`, `plan`.
6. `log_time` записи задачи и `utc_ns` события совмещаются через UTC: MCAP хранит начало часов
   исполнителя на стене (`wall_origin_ns`).

## Альтернативы

**Одна MCAP на миссию, пишет координатор.** Состояния шли бы по связи на частоте робота: координатор стал
бы ретранслятором телеметрии, а связь — узким местом. Отвергнуто.

**Одна MCAP на робота за всю миссию.** Метаданные `run` (ADR-0038) описывают один навык и одну цель.
Пришлось бы вводить границы задач внутри записи, и `read_record` перестал бы читать её как запись
прогона. Отвергнуто.

**Хронология в MCAP.** Сделала бы `mcap` обязательным для координатора. Строки JSON читает что угодно.
Отвергнуто.

## Последствия

- `coordinator/journal.py`. Запись задачи — тот же `McapRecorder`: его читают `read_record` и метрики
  фазы 4 без правок.
- Каталог прогона не версионируется и в хранилище не кладётся, как каталог обучения (ADR-0046).
