# 0008. Реестр величин `requires` закрыт, у каждой величины один источник

Статус: принято
Дата: 2026-09-12

Контекст: ADR-0001 вынес количественные требования навыка в блок `requires` со
сравнениями `>=`, `<=`, `==` и сказал, что валидатор сверяет их с `contract` и
`limits` профиля. Не сказано, какие имена величин допустимы и откуда каждая
берётся. Без этого `requires` — свободный словарь, то есть ровно тот случай,
который в ADR-0001 отвергнут для самих возможностей: опечатка `command_rate`
вместо `command_rate_hz` дала бы не ошибку, а требование, которое никто не
проверяет.

Решение: величины образуют закрытый реестр, и у каждой ровно один источник в
профиле.

| Величина | Источник |
|---|---|
| `dof` | длина `contract.joint_order` |
| `command_rate_hz` | `contract.command_rate_hz` |
| `state_rate_hz` | `contract.state_rate_hz` |
| `cartesian_velocity_max` | `limits.cartesian_velocity_max` |
| `gripper_width_m` | `limits.gripper_width_max` |

Имя вне реестра — ошибка при разборе, а не при сверке: неизвестное требование
обязано падать там, где его впервые прочитали.

Величина, которой профиль не объявляет, считается **невыполненным** требованием,
а не пропущенной проверкой. Это главный пункт карточки. Захват шириной «неизвестно»
и захват шириной 60 мм — разные вещи, и валидатор, существующий ради того, чтобы
молчаливое расхождение не доезжало до робота, не имеет права путать «не знаю» с
«подходит».

В реестр не попали величины, которые пришлось бы выводить. Например, «максимальная
скорость сустава» для робота — это вектор, и свести его к числу можно минимумом,
максимумом или средним; каждый вариант — правило вывода, а ADR-0001 запрещает
вывод следствий и для возможностей. Как только такая величина понадобится, она
появится в профиле явно, а не будет вычислена ядром.

Альтернативы:
(1) свободные имена, сверяемые по месту — отвергнута: опечатка даёт
    непроверяемое требование, то есть ложное чувство проверки; это тот же довод,
    по которому в ADR-0001 отвергнуты свободные строки возможностей;
(2) путь до поля профиля прямо в требовании (`contract.command_rate_hz: ">=50"`)
    — отвергнута: автор навыка начинает знать внутреннее устройство профиля, и
    любая перестановка полей ломает все навыки; имя величины — это интерфейс, а
    путь — реализация;
(3) считать отсутствующую величину выполненной — отвергнута по причине из
    решения: превращает проверку в необязательную;
(4) выводить величины из нескольких полей (минимум по вектору лимитов) —
    отвергнута: правило вывода в ядре — то самое знание не на своём месте,
    против которого написаны ADR-0001 и ADR-0002.

Последствия: добавление величины — правка реестра в ядре, то есть решение, а не
мелочь; зато список того, о чём навык может спросить, обозрим и документирован.
Автор навыка обязан различать дискретное (возможности) и количественное
(`requires`), и это различение теперь видно в ошибке валидатора: она называет
величину, сравнение и источник, откуда взято фактическое значение.
