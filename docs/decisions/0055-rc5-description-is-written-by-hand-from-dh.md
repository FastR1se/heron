# ADR-0055. Описание RC5 пишется руками по DH-таблице и сверяется с роботом на пробе

**Статус:** принято; применяет ADR-0009 и ADR-0048
**Дата:** 16.09.2026

## Контекст

- `description.urdf` в схеме профиля обязателен. Правила `urdf.*` — единственный способ платформы сверить
  описание с профилем: суставы, подвижность, пределы позиции и скорости с переводом единиц, корень, меши.
  Масс и инерций они не проверяют.
- ADR-0009: описание — вход платформы, генераторы его не порождают. Путь «руками» в руководстве есть.
- URDF, ROS-драйвера и симулятора RC5 у производителя публично нет (0.20). В API 1.4.1 есть DH-таблица модели
  RC5 (0.34): `alpha = (π/2, 0, 0, π/2, −π/2, 0)`, `a = (0, −0.405, −0.3722, 0, 0, 0)`,
  `d = (0.1725, 0.156, −0.1485, 0.1398, 0.1398, 0.1398)`, `theta` и `offset` нулевые.
- **Соглашение DH не названо** ни в коде, ни в руководстве. SDK прямую кинематику не считает — считает
  контроллер. Форма таблицы — та же, что у классических (дистальных) DH серии UR.
- Паспорт (0.18): оси 1, 2, 4, 5, 6 — ±360°, ось 3 — ±165°, все 180 °/с; масса 27 кг целиком. Масс и
  инерций звеньев нет. Чертёж RC5 — приложение 6.2 руководства ввода, в текстовой копии только подпись.
- В пакете RTD рядом с углами суставов приходит поза фланца `act_flange_x` (0.29) — посчитанная контроллером.
- ADR-0048: база закрепляется описанием — фиксированный сустав к звену `world`; платформа не закрепляет.
- Симуляционного двойника RC5 в фазе нет (план, «Не входит в фазу»).

## Решение

**1. `description.urdf` остаётся обязательным.** RC5 получает описание, написанное человеком по DH-таблице
API — вход, как требует ADR-0009.

**2. Описание кинематическое.** Звенья без `<inertial>`, без мешей. Выдуманные массы и инерции хуже их
отсутствия: они выглядят как данные. Описание, пригодное для симулятора, — решение того, кто будет строить
двойник RC5, с настоящими числами.

**3. Каждое число названо источником.** Шапка файла: DH — таблица модели API 1.4.1, соглашение —
**предположено классическим** по форме таблицы и подлежит проверке; это параметры модели, а не калибровка тела;
пределы позиции и скорости — паспорт. Звено `world` и фиксированный сустав к базе — по ADR-0048.

**4. Соглашение DH проверяется на роботе, а не выбирается.** Проба в `read_only` пишет серию пар
`act_q` / `act_flange_x`. Прямая кинематика описания по `act_q` сравнивается с `act_flange_x`. Расхождение
выше точности модели означает неверное соглашение или смещения нулей, и описание исправляется — до первого
движения.

**5. Пределы профиля уже паспорта.** Профиль сужает рамку под стенд; `urdf.position_limit_wider` и
`urdf.velocity_limit_wider` держат порядок «профиль внутри описания».

## Альтернативы

**Сделать `description.urdf` необязательным для робота без симуляции.** Робот без описания не сверяется ни с
чем: `joint_order` профиля нечем подтвердить, пределы не с чем сравнить, критерий 3 проверялся бы на профиле,
про который платформа ничего не знает. И «робот без симуляции» стал бы признаком профиля, от которого
пришлось бы ветвить правила. Отвергнуто.

**Порождать URDF из DH-таблицы генератором.** Платформа начала бы авторить кинематику — то, от чего отказался
ADR-0009, — и притом по таблице с неназванным соглашением. Отвергнуто.

**Приближённые массы и инерции** (27 кг поровну, цилиндры). Числа без источника в описании, которое потом
прочтёт симулятор как настоящие. Отвергнуто.

**Считать соглашение классическим без проверки.** Ошибка соглашения не видна ни одному правилу `urdf.*` и
проявилась бы только в двойнике или в декартовой задаче. Проба стоит одного чтения. Отвергнуто.

## Последствия

- В пакет RC — скрипт сравнения прямой кинематики описания с `act_flange_x` для пробы; расхождение по
  положению и ориентации — строкой эксперимента.
- Проба получает шаг: запись пар `act_q` / `act_flange_x` в нескольких позах, выставленных человеком в
  «Пульсе». Без движения из платформы.
- Прямая кинематика нужна пакету, а не ядру: ядро по-прежнему кинематику не считает.
- Руководство (критерий 10): путь «у производителя есть DH-таблица» — описание руками, соглашение проверяется
  по позе фланца, которую сообщает контроллер.
