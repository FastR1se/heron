# ADR-0067. Порядок задач — частичный и записан сверху вниз

**Статус:** принято
**Дата:** 19.09.2026

## Контекст

- Задачи разных роботов могут идти одновременно, а могут ждать друг друга: манипулятор отводит руку,
  прежде чем гуманоид поднимет свои. Без одновременности «два робота в одной миссии» — это два `run` по
  очереди, то есть то, что уже сделано в фазе 4.
- Деревья поведения отложены (раздел 15): платформа исполняет последовательность навыков.
- Один робот исполняет один навык за раз: исполнитель один на время жизни связи (ADR-0016).
- В общем мире одновременное движение двух роботов — решение о безопасности (раздел 12), а не
  подробность исполнения.

## Решение

1. **`after`** — список задач, успешного завершения которых задача ждёт.
   - Поле не задано — задача ждёт предыдущую в файле. Миссия читается сверху вниз, как сценарий.
   - `after: []` — не ждёт никого.
   - `after: [a, b]` — ждёт обе.
2. **`after` называет только задачи, записанные выше.** Имя, которого нет, — ошибка
   `mission.dependency_unknown`. Сама задача или задача ниже — `mission.dependency_forward`. Циклов и
   взаимных ожиданий нет по построению: у любого частичного порядка есть запись сверху вниз, так что
   выразительность не теряется.
3. **Задачи одного робота идут в порядке файла**, даже если зависимости позволили бы иначе. Робот не
   начинает задачу, пока не выполнены все его задачи выше.
4. **Условие ожидания одно — успех.** Ветвлений, условий, повторов и запасных задач нет: это и есть
   дерево поведения, отложенное разделом 15.
5. **Одновременность пишется явно.** Две задачи разных роботов идут вместе, только если автор так
   записал `after`.

## Альтернативы

**Строгая последовательность всей миссии.** Как `run_tasks`, только для комплекса. Роботы никогда не
работают вместе, и фаза 8 не доказывает ничего сверх фазы 4. Отвергнуто.

**Одновременность по умолчанию** — задачи без `after` стартуют сразу. Пропущенное поле двигало бы двух
роботов в общем мире одновременно. Отвергнуто.

**Произвольный граф с поиском циклов.** Вместе с неявным порядком задач одного робота даёт взаимные
ожидания, которых в тексте не видно: робот A ждёт задачу робота B, та ждёт следующую задачу A.
Правило «только выше» даёт ту же выразительность и не требует объяснять тупик. Отвергнуто.

**Дерево поведения** (последовательность, выбор, условие, повтор). Отложено разделом 15 и остаётся
отложенным: фаза 8 доказывает раздачу по возможностям, а не язык управления. Отвергнуто.

## Последствия

- `Mission.waits_for(i)` раскрывает умолчание. План хранит уже раскрытые `after`.
- Планировщик координатора — перебор задач в порядке файла: задача стартует, когда её `after`
  выполнены, её робот свободен и его задачи выше выполнены.
