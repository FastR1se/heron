# ADR-0068. Координатор — процесс, каждый робот — процесс своего исполнителя; связь — строки JSON по TCP, план — файл

**Статус:** принято
**Дата:** 19.09.2026

## Контекст

- Раздел 4:
  - контейнер робота — единица развёртывания: исполнитель, навыки, адаптер;
  - координатор — отдельный контейнер: очередь задач, распределение по возможностям, контроль
    выполнения;
  - `Executor` намеренно ведёт одного робота: «раздача задач — дело координатора и отдельная единица
    развёртывания».
- Факты из кода и прогонов фазы 4:
  - адаптер G1 отвергает процесс с загруженным `rclpy`: CycloneDDS 0.10.2 производителя не уживается с
    `rclpy` в одном процессе (ADR-0022, ADR-0029, `unitree_g1/cyclone.py`: `CANNOT_SHARE_A_PROCESS`);
  - адаптер `ros2_control` без `rclpy` не работает;
  - в этапе 7 фазы 4 (`scripts/phase4-stage7.sh`) `run` G1 шёл из окружения с SDK производителя, а `run`
    манипулятора — из окружения с подключённым ROS 2. Это разные интерпретаторы и разные переменные.
- Значит, два робота комплекса не помещаются в один процесс — ни потоками, ни как-либо ещё.
- Compose не порождается (ADR-0010). Настройка сети между контейнерами отложена (раздел 15).
- Мир поднимается отдельной командой (`sim run`), `run` к нему присоединяется в его окружении (ADR-0039).

## Решение

1. **Координатор — процесс команды `mission run`.** Он проверяет сцену и миссию, пишет план в каталог
   прогона и ждёт роботов. Потом раздаёт задачи и собирает исходы.
2. **Каждый робот — процесс `mission robot <каталог> --robot <id>`**, то есть контейнер робота раздела 4.
   Процесс:
   - читает план;
   - применяет окружение мира с проверкой расхождений (ADR-0039);
   - строит навыки своих задач до связи (ADR-0047);
   - проверяет требования адаптера (ADR-0025) и подключается;
   - докладывает готовность и исполняет задачи по команде тем же `Executor`, что `run`. Исполнитель один
     на всё время связи (ADR-0016).
3. **План — файл** `plan.json`.
   - Содержит: назначение задач, роботов, ключи связей, `contract_id`, окружение мира, адрес
     координатора, признак записи.
   - `plan_id` — хеш канонической формы (ADR-0006). Робот представляется им, и чужой прогон к
     координатору не подключится.
   - Процесс робота сверяет `contract_id` профиля с планом: профиль, изменённый после проверки, —
     отказ.
4. **Живая связь — строки JSON по TCP на `127.0.0.1`**, только ASCII, порт выбирает система и пишет в план.
   - От робота: `hello`, `ready`, `refused`, `finished`.
   - От координатора: `welcome` или `rejected` в ответ на `hello`, затем `start`, `cancel`, `end`.
     Ответ приходит до подключения связи: процесс чужого прогона не трогает робота.
   - Телеметрии в связи нет: состояние остаётся у исполнителя (ADR-0070).
5. **Потеря связи — отмена.** Процесс робота, потерявший координатора, останавливает текущую задачу
   (ADR-0069) и завершается. Робот не продолжает работу без того, кто знает миссию.
6. **Кто запускает процессы роботов, решает флаг.**
   - `--spawn` (умолчание) — запускает координатор: тем же интерпретатором, через `SubprocessLauncher`,
     в своей сессии (ADR-0037). Ctrl+C терминала получает только координатор и останавливает роботов
     через связь.
   - `--no-spawn` — процессы запускаются отдельно, каждый в своём окружении: так на Linux G1 идёт из
     окружения SDK, манипулятор — из окружения ROS 2.
   - Код процесса робота один. Сухой прогон печатает команды процессов (ADR-0011).
7. **`run` не меняется.** Один робот, один процесс, без координатора; исполнитель общий.

## Альтернативы

**Потоки в одном процессе.** Невозможно для G1 рядом с `rclpy` (факт выше). Кроме того, роботу
понадобилось бы окружение соседа. Отвергнуто.

**Связь через ROS 2: топики, действие.** Процесс G1 не может загрузить `rclpy`. Ядро обязано работать
без ROS 2: `dummy`, CI, Windows. Отвергнуто.

**Каналы stdin/stdout запущенных координатором процессов.** Координатору пришлось бы знать
интерпретатор и окружение каждого робота, а процесс, запущенный отдельно (контейнер, другой терминал),
не подключился бы. TCP допускает оба способа запуска. Отвергнуто.

**Почтовый ящик из файлов в каталоге прогона.** Опрос файлов по таймеру. Смерть координатора роботу не
видна, пока тот не придумает сердцебиение, а у сокета её показывает конец потока. Отвергнуто.

**Брокер сообщений или Zenoh.** Сеть между контейнерами отложена (раздел 15). Внешняя зависимость ради
связи на одной машине. Отвергнуто.

## Последствия

- Группа команд `mission`: `validate`, `run`, `robot`. В `cli/main.py` — одна строка подключения.
- Модули: `coordinator/plan.py`, `protocol.py`, `server.py` (сторона координатора), `robot.py` (сторона
  робота), `coordinator.py` (планировщик).
- Протокол внутренний: в `PUBLIC_MODULES` не входит, пакету робота он не нужен.
- Адрес в фазе 8 — только петлевой. Контейнеры потом изменят адрес, а не протокол.
- На Windows процесс робота отдельной сессии не получает: Ctrl+C консоли доходит и до него. Исполнитель
  сначала останавливает робота (ADR-0026), координатор видит отказ — исход тот же.
