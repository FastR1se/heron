# ADR-0053. SDK производителя не реагирует за платформу

**Статус:** принято; применяет ADR-0026 и ADR-0029 к пакету RC
**Дата:** 16.09.2026

## Контекст

Из исходника API RC 1.4.1 (факты 0.35–0.38):

- `RobotApi.__init__` ставит `sys.excepthook = self._exit_program` и регистрирует тот же обработчик в `atexit`.
  Обработчик пишет в журнал SDK и закрывает сокеты.
- SDK держит два недемонических потока: приём RTD и `StateHandler` с тактом 10 мс.
- `StateHandler` на `emergency_stop`, `fault`, `violation` и `failure` бросает исключение **из фонового
  потока**: SDK закрывает сокеты и вызывает свой обработчик разрыва. Подавляется флагом конструктора
  `ignore_controller_exceptions`.
- `get_data()` отдаёт живой объект `RTD`. Приёмный поток пишет в него поле за полем без замка, между полями
  вызовов ввода-вывода нет.

Со стороны платформы: отказ в команде — `CommandRefusedError`, исполнитель сначала останавливает робота,
потом сообщает (ADR-0026). Сторожевой таймер — функция исполнителя (ADR-0015). Канал внедряется, настоящий
открывается при подключении, SDK за ним (ADR-0029 — так устроен пакет G1).

Если оставить SDK как есть, нажатие кнопки на роботе выглядит для исполнителя не как «робот в аварийном
останове», а как связь, пропавшая посреди такта: `read_state` бросает, останов отправить некуда, причина
теряется в трассировке фонового потока.

## Решение

**1. Реакция на статус безопасности — решение адаптера и исполнителя, не фонового потока SDK.** Канал
создаёт `RobotApi` с `ignore_controller_exceptions=True`. Статус безопасности, состояние контроллера и режим
движения приходят в каждом показании; адаптер переводит их в фазу движения (`halted`, ADR-0049) и в отказ
команды (`CommandRefusedError`) при статусе вне `normal`/`reduced` или контроллере не в `run`. Физический
останов по-прежнему делает контроллер: флаг меняет того, кто сообщает, а не то, что происходит с роботом.

**2. Процесс принадлежит платформе.** `RobotApi` создаётся только при открытии настоящего канала внутри
`connect` — не при импорте пакета, не при разрешении плагина и не в сухом прогоне. Сразу после создания
канал возвращает прежний `sys.excepthook`. Обработчик `atexit` остаётся: он только закрывает сокеты, и при
аварийном выходе процесса это полезно. `disconnect` вызывает `disconnect` SDK на всех путях, иначе
недемонические потоки SDK не дадут процессу завершиться.

**3. Одно показание — одна копия.** Канал копирует нужные поля `RTD` одним проходом, без вызовов между
полями, и дальше работает с копией. Согласованность полей держится на том, что приёмный поток SDK не
отпускает GIL между полями. Это условие, а не гарантия: оно записывается в пакет, и сборка CPython без GIL
для пакета не поддерживается.

**4. Вендорский журнал — в журнал процесса.** По умолчанию SDK пишет в консоль своим обработчиком и форматом
(файл журнала выключен). Канал передаёт SDK логгер процесса (`logger=`): сообщения SDK идут туда же, куда
сообщения платформы, и файл журнала SDK не включается — его путь по умолчанию лежит рядом с исполняемым
файлом, то есть там, куда платформа не пишет.

## Альтернативы

**Оставить реакцию SDK.** Статус безопасности превращается в разрыв связи из чужого потока (контекст).
Отвергнуто.

**Разбирать RTD самим, без `RobotApi`.** Согласованность снимка стала бы полной, но пакет повторял бы протокол
производителя — формат пакета, порты, версии ядра — и расходился бы с ним на каждом обновлении прошивки.
Совместимость версий проверяет `connect` SDK (0.6); повторять её нельзя. Отвергнуто.

**Запускать SDK в отдельном процессе.** Изолирует `excepthook`, потоки и GIL, но добавляет межпроцессный
протокол ради того, что закрывается тремя строками при создании канала. Отложено до SDK, который так не
закрывается.

**Проверять согласованность двойным копированием.** Две одинаковые копии могут обе попасть внутрь одной
записи; условие о GIL честнее видимости проверки. Отвергнуто.

## Последствия

- Урок для любого пакета производителя, записывается в руководство (критерий 10): SDK с собственными
  потоками не должен решать, когда закончилась связь; флаги вроде `ignore_controller_exceptions` ищутся в
  исходнике до кода адаптера.
- Записывающий канал пакета воспроизводит показания со статусом `emergency_stop`: отказ в команде и фаза
  `halted` проверяются без робота.
- Что именно SDK видит при нажатии кнопки — статус до разрыва или разрыв — факт 0.25; решение от него не
  зависит, карточка аварийного останова — зависит.
