# ADR-P8E. Отказ задачи останавливает комплекс: движущиеся роботы — остановом, новые задачи не начинаются

**Статус:** принято
**Дата:** 19.09.2026

## Контекст

- Один робот (ADR-0015, ADR-0026):
  - последовательность задач обрывается на первом отказе;
  - отказ адаптера в команде — сначала останов, потом отчёт;
  - любое иное исключение — сначала останов, потом исключение дальше.
- В комплексе на отказе одной задачи другие роботы могут быть в движении.
- Остановить навык снаружи исполнителя было нечем: только `KeyboardInterrupt` в том же процессе.
- Аварийный останов у разных роботов значит разное. У G1 это демпфирование, `kp = 0` (ADR-0028):
  стоящий без баланса робот от него падает.

## Решение

1. **Первая неуспешная задача останавливает комплекс.** Неуспех — это любое из:
   - `FAILURE` навыка;
   - сторожевой таймер;
   - отказ адаптера;
   - исключение;
   - потеря связи с роботом;
   - отказ робота при подготовке.
2. **Что делает координатор:**
   - отменяет каждую идущую задачу;
   - новых не начинает;
   - ждёт исходов отменённых задач;
   - завершает миссию с `FAILURE`, называя первую неуспешную задачу и её причину.
   Отменённые задачи получают состояние `cancelled` и причину «отменена: …». Задачи, до которых не
   дошло, — `not_started`.
3. **Отмена — тот же путь, что сторожевой таймер.** У `Executor` появилась `Cancellation`: запрос снаружи
   цикла, который проверяется в начале каждого такта. Сработал — сначала `emergency_stop` и отмена
   навыка, потом `FAILURE` с причиной (ADR-0026). Отдельного «мягкого» пути нет.
4. **Робот, не исполняющий задачу, не трогается.** Ему не отправляется ничего, в том числе останова.
5. **Ctrl+C у координатора — та же остановка**, исход `interrupted`. Потеря связи на стороне робота — та же
   отмена (ADR-P8D).
6. **Робот, отказавший при подготовке, не даёт миссии начаться.** Ни один робот не двигается.

## Альтернативы

**Продолжать независимые ветви.** Независимость по `after` — утверждение о порядке, а не о пространстве:
роботы делят мир, и остановленный посреди движения манипулятор мог остаться на пути соседа. Миссия
всё равно не выполнена. Отвергнуто.

**Останавливать всех роботов, включая стоящих без задачи.** Это команда роботу, которого никто не
просил двигать. Для робота без встроенного баланса демпфирующий останов — падение. Отвергнуто.

**Повтор задачи или поле `on_failure`.** Это язык восстановления, то есть дерево поведения (раздел 15).
Отвергнуто.

## Последствия

- `Executor.run(..., cancel=Cancellation)` и `run_task(..., cancel=...)`. Без аргумента поведение
  прежнее; `run` его не передаёт.
- После отказа роботы стоят там, где их застал останов. Восстановление — дело человека, как после
  `run`.
- Задержка отмены — не больше одного периода команды робота: у командного `rest_arm` 0.5 с. В командном
  классе движение планирует контроллер, и останов отменяет его цель (ADR-0049, ADR-0060).
