# ADR-0041. Отображение выхода политики в команду — нормативная часть действия

**Статус:** принято; дополняет ADR-0004, ADR-0006, ADR-0019
**Дата:** 16.09.2026

## Контекст

Факты этапа 0 фазы 6 (план `docs/plans/phase6-learned-skill.md`, эксперимент 0002):

- Действие по положению в Isaac Lab — `processed = raw · scale + offset`, затем клип по суставу **после**
  масштаба, в радианах; при `use_default_offset=True` смещение — поза по умолчанию артикуляции (факт 0.2). У
  Franka reach `scale = 0.5` вокруг позы по умолчанию (0.3).
- `rsl_rl` клипует **сырой** выход сети симметрично, до шага среды: `torch.clamp(actions, -c, c)` в
  `RslRlVecEnvWrapper.step`; при `clip_actions = None` не клипует вовсе.
- Выход обученной сети не ограничен: ±8.5 на входах N(0, 1) (0.17).
- Контракт знает `action.type` и `action.clip`, и больше ничего. Смысл `clip` не определён: в коде его
  только печатает `profile show`.

Сеть, обученная с `scale 0.5` вокруг позы отсчёта, и та же сеть, чей выход исполнитель примет за радианы,
— разные политики с одним `contract_id`. Это ровно тот класс ошибки, против которого написан инвариант 6.

## Решение

**1. Поза отсчёта — поле контракта `default_pose`:** по суставу, в порядке `joint_order`, в `angle_unit`.
Необязательное, нормативное, если задано. Поле одно и для действия, и для наблюдения (ADR-0042): это одна
величина, и записана она один раз. В среде обучения это `init_state.joint_pos` артикуляции для суставов
контракта.

**2. Масштаб и смещение — поля действия.** `action.scale` — список по суставу, ненулевой, только у действий по
суставам (`joint_position`, `joint_velocity`, `joint_torque`). `action.offset` — закрытый словарь: `zero`
(умолчание) или `default_pose`; второе допустимо только у `joint_position` и только при заданном
`default_pose`. Скаляр `scale` не принимается: у `kp` и `kd` тоже список, и одна величина не получает двух
форм записи.

**3. Отображение одно на оба мира:**

```
u  = clip(a, action.clip)            a — выход сети
q* = u ⊙ scale + origin              origin = default_pose при offset: default_pose, иначе 0
```

Незаданный `scale` — единица. Среда обучения собирает из этого терм действия, `LearnedSkill` (ADR-0047)
применяет то же самое. Команда адаптеру по-прежнему — абсолютные значения типа `action.type`.

**4. `clip` — над сырым выходом сети, до масштаба;** пара без единиц. Клип Isaac после масштаба, в единицах
сустава, не используется: границы в единицах сустава — это `limits.joint_position`, и второй раз их не
описываем. Среда обучения клипует выход до терма действия, поэтому `previous_action` видит его уже
клипнутым (ADR-0042).

**5. Незаданное необязательное нормативное поле в каноническую форму не попадает.** Правило ADR-0019 для `kp`
и `kd` становится общим: `default_pose` и `scale` при отсутствии, `offset` при `zero`. Идентификатор всякого
существующего контракта не меняется; золотой тест остаётся как есть.

**6. Цель, которую политика способна приказать, лежит в рамке — проверяется до запуска.** Правила профиля:

- `contract.default_pose_outside_limits` — ошибка: поза отсчёта вне `limits.joint_position`;
- `contract.action_outside_limits` — ошибка: у действия `joint_position` с заданным `clip`, `scale` или
  `offset: default_pose` множество `origin + [clip_lo, clip_hi] · scale` не лежит в рамке по какому-либо
  суставу; заданы масштаб или смещение без `clip` — та же ошибка (цели не ограничены);
- `contract.action_envelope_unknown` — предупреждение: проверять не с чем, у профиля нет рамки.

Ошибка, а не предупреждение: цель вне рамки — это отказ адаптера посреди движения (ADR-0026), а инвариант 6
требует найти его до движения.

## Альтернативы

**Масштаб и смещение в манифесте, вне контракта.** Артефакт сверяется по `contract_id`, и сеть с другим
масштабом прошла бы сверку. Отвергнуто.

**`offset` списком чисел.** Поза отсчёта записана дважды — в действии и в наблюдении — и может разойтись.
Отвергнуто по сквозному принципу.

**`offset` булевым полем.** Закрытый словарь оставляет место относительному действию от измеренной позы
(`RelativeJointPositionAction` в Isaac Lab) без смены типа поля. Сейчас этот член не добавляется: примера нет.

**Новый тип действия `joint_position_rel`.** Тип действия — это то, что уходит адаптеру и из чего выводятся
контроллер и топики (ADR-0014). Адаптер при любом отображении получает абсолютные положения. Отвергнуто.

**Клип в единицах сустава после масштаба, как в Isaac Lab.** Одна пара на все суставы бессмысленна, а пара по
суставу — второе описание `limits.joint_position`. Отвергнуто.

**Молчаливая проекция цели на рамку в `LearnedSkill`.** Прячет дефект политики. В среде обучения сустав
держит предел URDF, а не рамка профиля — законы в двух мирах разошлись бы. Отвергнуто в пользу проверки до
запуска.

## Последствия

- `Contract` получает поле `default_pose`, `ActionSpec` — поля `scale` и `offset`, реестр `ActionOffset`.
  Появляются три правила профиля и ошибки разбора (длины, нули, смещение без позы).
- У профиля одно отображение: две политики с разным масштабом на одном контракте несовместимы — это прямое
  следствие ADR-0004, у робота один контракт. Если это станет помехой, решать будет новая карточка.
- Для навыка кодом `clip`, `scale` и `offset` ничего не значат: сырого выхода у него нет.
- `arm6` получает `revision: 2` вместе с ADR-0042 и ADR-0045; числа — на этапе 2.
- В Isaac Lab: `JointPositionActionCfg` с `scale`, `use_default_offset` по `offset`, `preserve_order=True`,
  `clip=None`; сырой выход клипует бэкенд. Симметричная пара годится и для `clip_actions` обёртки `rsl_rl`,
  несимметричная — только для своего клипа.
